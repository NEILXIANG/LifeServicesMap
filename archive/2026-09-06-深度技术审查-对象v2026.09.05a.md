## 一、本轮最重要的发现

### J1（P1）—— 城市/省级事实硬编码在"通用引擎"里，而校验脚本查不出来

这是本轮唯一一个同时命中三个维度（数据准确性 + 扩展性 + 安全风险）的问题。

在 `src/engine.html`——也就是那个按设计"不应包含任何城市数据"的文件里——五种语言的界面文案中
硬编码了这些**具体到城市和省份的事实**：

| 内容 | 出现次数 | 性质 |
|---|---|---|
| `8-1-1` | 13 | BC 省健康咨询热线，**省级**事实 |
| `250-828-3000` | 10 | Kamloops RCMP 非紧急电话，**城市级**事实 |
| `1-800-665-8779` | 10 | BC 省租客维权处 RTB，**省级**事实 |
| `Umo` | 10 | BC Transit 的交通卡品牌，**运营商级**事实 |
| `$2.25 / $4.50 / $55` | 10（含法/西两种数字格式） | Kamloops 公交票价，**城市级**事实 |

而 `validate.py` 第 16 节那条"引擎里不许有城市数据"的检查，实际只查五个**结构性标记**
（`const P=`、`const BR=`、`const CITY=`、`const RI=`、`guideCity=`）。第 15 节那条"翻译文案里
不许出现字面城市名/机构名"能拦住名字（所以才有 `{CITY}`/`{TRANSIT}` 占位符），但**拦不住数字和
品牌词**。所以这些事实一路畅通地留在引擎里，而校验全绿——问题不只是漏了，是**校验给了一个
虚假的安全感**。

三个后果，按严重程度排：

1. **扩展到别的城市会静默给出错误信息**。照 `DATA-SCHEMA.md` 的五步流程做一个 Kelowna 版，
   数据文件全换掉、校验全过、回归全绿——然后这个 Kelowna 版会理直气壮地告诉当地新居民打
   `250-828-3000`（那是 Kamloops 的 RCMP）、票价 $2.25（Kelowna 是另一个运营商、另一套票价）。
   做 Calgary 版还会给出 BC 省的 `8-1-1` 和 RTB 电话，而 Alberta 的对应机构完全不同。这不是
   "多花点功夫改"的麻烦，是**会传播错误信息的缺陷**，而且是在这个工具最要命的内容上（新居民
   照着一个错的非紧急/健康热线打电话）。
2. **这些事实游离在整套数据治理体系之外**。数据文件里每条记录都有 `src` 来源标签、`v` 核实
   日期、能被 `export-open.py` 导出、能被 `check-links.py` 检查。引擎文案里的这些电话和票价
   **一样都没有**——没有来源、没有核实日期、不在任何导出和检查的范围内。BC Transit 涨过价、
   RTB 换过号码，页面都会毫不知情地继续用五种语言展示旧数字，而"最后核实：{DATE}"那行字还在
   暗示这些内容是新的。
3. 顺带暴露了校验脚本的一个盲区，而这个项目的校验规则一向是"每条规则都对应一个真实漏网的
   问题"——这条应该补上。

**修复方案**（三步，可以分开做）：
- 把这些事实搬进数据文件：票价放 `CITY.transit.fare`，紧急/求助电话放 `CITY.emergency` 数组，
  引擎文案改用 `{FARE}`、`{HEALTHLINE}`、`{RCMP}`、`{RTB}` 这类占位符（`tpl()` 已经有现成的
  占位符展开机制，加几个 key 就行）。
- 给 `validate.py` 加一条规则：引擎的翻译文案里出现货币金额（`$\d`）或电话号码模式
  （`\d{3}-\d{3}-\d{4}`、`\d-\d{3}-\d{3}-\d{4}`、`8-1-1` 这类）就直接 fail。这条规则和现有那些
  "每条都对应一次真实漏网"的规则是同一个性质。
- 搬进数据文件之后，这些事实自然就获得了 `v` 核实日期和 `src` 来源标签，纳入正常的复核节奏。

### J2（P2）—— 最常用的筛选面板没有焦点管理，而两个不常用的弹窗反而做得很标准

实测（Playwright，1100×800 桌面端）：

| 面板 | 打开后焦点落在哪 | 连按 3 次 Tab 之后 | Escape |
|---|---|---|---|
| **主筛选面板**（区域/分类/公交/收藏都在这里） | `<body>`，**焦点没有进入面板** | 跑到面板**背后**被遮住的顶部语言按钮上 | ✅ 能关 |
| 新居民指南弹窗 | `guideClose` 按钮，正确 | 仍在弹窗内（焦点被正确困住） | ✅ 能关 |

原因在代码里很清楚：`trapTab()` 这个焦点陷阱函数只注册给了 `noteBackdrop` 和 `guideBackdrop`
两个全屏弹窗，**没有注册给 `#panel`**。而 `#panel` 恰恰是使用频率最高的那个——区域筛选、分类
筛选、公交线路、收藏夹四个功能全在里面。

对键盘用户和读屏用户来说，点开"分类"之后焦点原地不动，然后 Tab 会走到被遮住的背景内容里去，
这是一个视觉上是模态、语义上不是模态的面板。顺带还发现一个次要问题：弹窗关闭后焦点没有还给
当初打开它的按钮（实测落到了第一个语言按钮上），标准做法是还回触发按钮。

**修复方案**：给 `#panel` 也注册 `trapTab`，打开时把焦点移到 `#panelClose`，关闭时把焦点还给
触发按钮（`openPanel` 时记一下 `document.activeElement`，`closePanel` 时 `.focus()` 回去）。
现成的 `trapTab` 直接复用，改动量很小。

### J3（P2）—— 指南正文近 1.4 万字的事实性内容，完全不在数据治理体系之内

新居民指南的正文（在引擎里，五种语言，中文版约 13,800 字符）里塞满了具体的、会过期的事实：
电话号码（Access Pro Bono `604-878-7400`、CRT `1-844-322-2292`）、金额门槛（BC 民事解决法庭
小额索赔 `$5,000` 上限）、机构名称、资格条件。**这些内容一条 `src` 没有、一个核实日期没有、
不在 `check-links.py` 的检查范围内、也不在 `export-open.py` 的导出范围内。**

需要说清楚的是：我今天专门去 BC Civil Resolution Tribunal 官网核对了那个 `$5,000` 的门槛，
**目前仍然是准确的**（2025 年 3 月那次修法扩大的是可受理的纠纷类型，没有调整金额上限）。
所以问题不是"内容错了"，而是——**如果哪天它错了，这套系统里没有任何机制会发现**。地点数据
有三色来源标签、逐条核实日期、外链检查脚本；指南正文这个体量更大、后果更重（法律和福利信息）
的部分，一样都没有。

**修复方案**：给指南按小节加一个轻量的核实标记（比如每个 `guide*` 小节加一个 `verified:'2026-09'`
字段，在小节标题旁显示），并把指南里出现的外部电话/网址纳入 `check-links.py` 的扫描范围。
不需要做成和地点数据一样重的机制，关键是让"这段内容上次是什么时候看过的"变成可见的。

### J4（P2）—— 109 个外链从未被验证过，而且当前环境依然验证不了

数据里有 **109 个不重复的外部网址**。项目自己的状态文档里写着 `check-links.py` "需要在不经
代理的终端里跑"——本轮我又试了一次：抽了 14 个（学校官网、移民服务、RCMP、美术馆等）逐个
请求，**全部在 CONNECT 阶段被沙箱的出口代理 403 拒绝**，一个都测不了。也就是说这 109 个链接的
健康状况到今天为止仍然是完全未知的，而 33 个是深链接（最容易失效的那种）。

现在页面已经公开部署，一个点开是 404 的官方链接，比放在本地文件里的时候更伤信任。

**修复方案**：这件事只能在你自己的 Mac 终端里做（不经过这个云沙箱的代理）——
`cd` 到项目目录跑 `python3 check-links.py`，把结果日期记进 `kamloops-map-status.md`，之后
每季度跑一次。这是本轮所有条目里最"只需要五分钟、但只有你能做"的一件。

### J5（P2）—— 公开部署之后才出现的三个缺口

这几条在文件还只是本地 HTML 的时候不成立，现在部署到了 `*.pages.dev` 就成立了：

- **没有 `og:image`**：页面有 `og:title` 和 `og:description`，但没有预览图。你们打算用链接和
  二维码分享给其他新移民家庭——在微信、WhatsApp、iMessage 里发出去时，链接预览会是一块空白，
  点击率和"这看起来是个正经东西"的第一印象都会打折。这恰恰是部署这件事的主要目的。
- **没有 web app manifest / `apple-touch-icon` / `theme-color`**：手机上"添加到主屏幕"是这类
  工具最自然的重复使用方式（比每次翻聊天记录找链接方便得多），但现在加到主屏幕会得到一个
  通用图标、没有独立窗口模式、地址栏也没有主题色。
- **没有对搜索引擎索引做过决定**（没有 `robots` meta、没有 canonical）。这一条要和第四轮的
  **G2（个人邮箱明文写在页面里）** 连起来看：本地文件时代邮箱只有你自己看得到，公开部署 +
  被搜索引擎索引之后，`neilxiang@hotmail.com` 就是一个可以被爬虫直接收割的目标。两件事叠加，
  G2 的优先级实际上比第四轮评估时更高。

**修复方案**：做一张 1200×630 的地图截图当 `og:image`（可以内联成 data URI，保持单文件特性，
代价是文件大几十 KB；也可以作为独立文件和 HTML 一起部署）；加 `theme-color` 和一个极小的
manifest + apple-touch-icon；同时把 G2 一并处理掉（换成项目专用邮箱，或者做最简单的 JS 拼接
混淆）。

## 二、次要发现

### J6（P3）—— 界面里有 6 档小于 12px 的字号，其中 9.5px 用在了内容文字上

实测页面用到的字号：9 / 9.5 / 10 / 10.5 / 11 / 11.5 / 12 … 18px。其中 9.5px 用在两处**承载
内容**的地方：弹窗里的分类/区域标签（`.tag`，就是截图里"Medical"、"South Kamloops/Downtown"
那两个小色块），以及地图上的公交站名标签。

需要说明的是，**颜色对比度这一项全部达标**（我按 WCAG 公式算了主要配色组合）：

| 组合 | 对比度 | 标准（正文 ≥4.5） |
|---|---|---|
| 正文 `#202124` / 页面底 `#f8f9fa` | 15.27 | ✅ |
| 次要文字 `#5f6368` / 卡片白 | 6.05 | ✅ |
| 链接 `#1967d2` / 卡片白 | 5.37 | ✅ |
| 绿色来源标签 `#188038` / 卡片白 | 5.02 | ✅ |

所以这纯粹是**尺寸**问题，不是颜色问题，主要影响目标用户里年纪较大或视力一般的人——而这恰好
是新移民家庭里很常见的一类使用者（帮父母查诊所、查公交）。

**修复方案**：把承载内容的 `.tag` 从 9.5px 提到 11px（弹窗里空间充裕，不会引起换行）；地图
站名标签因为密度限制可以保留小字号，但可以考虑 10.5px。纯装饰性的箭头/角标（9px 的 `.chev`）
不用动。

### J7（P3）—— 属性插值没有转义，现在安全是"碰巧"而不是"被保证"

代码里大量使用 `innerHTML` 拼接，其中把文案插进了 HTML 属性，例如：
`'<button class="grp-check" aria-label="'+GN[grp.k][L_]+'">'`。这里没有任何转义函数。

我把全部 CI/RI/GN/UI 的属性用字符串、以及 249 条地点名称和全部五语言备注都扫了一遍：
**没有任何一条包含 `"`、`<` 或 `>`**，所以目前没有实际问题，也不构成 XSS（这些文本全部是
作者自己写的，不是用户输入）。但这是"碰巧没踩到"，不是"踩不到"——哪天写一条备注叫
`老板说"随便看"`，属性就断了，界面会以一种很难排查的方式坏掉。

**修复方案**：给 `validate.py` 加一条规则——地点名称、备注、分类/区域/分组标签里不许出现
`"`、`<`、`>`。这和这个项目现有的那些校验规则（"名字只差 ⭐ 前缀"、"地址里不许有中文"、
"户外场所不许声称 24 小时"）是完全一样的性质：把一次潜在的漏网固化成一条守得住的规则。

## 三、本轮验证通过、确认没问题的部分

这些是我实际测过、结果是好的，记录下来是为了以后不用重复怀疑：

- **安全性经受住了实测**：
  - 在搜索框输入 `<img src=x onerror=alert(1)>` 重复 20 次 → DOM 里**没有**注入任何原始 HTML，
    0 个页面错误（空状态文案用的是固定 UI 字符串，不回显搜索词；按钮用 `textContent`）。
  - 恶意收藏导入码 `KAM1:<script>alert(1)</script>.zzzz.xxxx…` → 被 `parseFavCode()` 按真实
    地点 ID 白名单过滤，导入 0 条，提示正常，0 个页面错误。这个白名单过滤是写得对的。
  - 破坏 `localStorage`（收藏写成非法 JSON、语言写成 `zz`、版本号写成数组）后刷新 →
    **0 个页面错误**，干净地回落到英文默认。三处 `try/catch` 都真的兜住了。
- **性能没有问题**：手机视口下首次内容绘制 380ms、DOM 完成 505ms、682 个 DOM 节点、
  JS 堆约 10MB。对一个 672KB 的单文件来说是好成绩，不需要优化。
- **"完全离线可用"的说法是真的**：构建产物里外部 `<script src>` **0 个**、外部样式表 **0 个**
  ——Leaflet 确实被 `build.py` 内联了（`src/engine.html` 里那三行 cdnjs 引用是构建前的源文件
  写法，不进成品）。而且回归测试里有一项专门测"聚合插件加载失败时的降级"，也是通过的。
- **Escape 键的处理是分层正确的**：指南弹窗 → 数据说明弹窗 → 筛选面板 → 地图气泡，永远关掉
  最上面那一个，这个实现比大多数项目细致。
- **没有时区陷阱**：营业时间是静态区间渲染，代码里没有 `new Date()`/`getHours()` 参与判断，
  所以不会出现"在国内看 Kamloops 的店显示营业中"这种错误。
- **`$5,000` 那个法律门槛是准确的**（今天去 CRT 官网核对过）。
