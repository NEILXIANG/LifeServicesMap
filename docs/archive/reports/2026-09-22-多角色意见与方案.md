# Kamloops 生活指南：14 种角色的意见与方案（暂不修改）

> 日期：2026-09-22
> 依据：
> - 目前的产品状态：约 300 个地点、14 张办事卡、6 种语言、求助面板、公交线路、传单
> - 9-21 全面检查的结论
> - 30 家机构的外联情况（1 家回复）
>
> 每条意见都标了：
> - **优先级**：P0 = 影响安全或信任，P1 = 明显提升价值，P2 = 锦上添花
> - **成本**：S = 半天以内，M = 1–3 天，L = 一周以上，或需要外部配合

---

## 一、先说结论：所有角色反复提到的 6 件事

1. **"谁在维护、多久更新一次"必须让人一眼看到。**
   - 政府、图书馆、移民中心、非营利机构都不敢推荐一个说不清维护者的网站。
   - 这是外联没有回复的核心原因之一。
   - 方案：
     - 做一个公开的"关于与维护"页：维护人、更新频率、纠错渠道、最近 30 天的改动记录。
     - 每条地点显示"核实于 / 收录于"。这一条已经做了。
2. **把"一个人维护"的风险变成"机构可以参与"。**
   - 数据靠个人核对，规模上不去，也不稳定。
   - 方案（按投入从小到大）：
     - 给机构一个"更正本机构信息"的专用入口（表单 + 邮件确认）；
     - 接入市政府开放数据和 bc211 的更新渠道；
     - 长期可以找一家本地机构托管，比如图书馆或 Kamloops Connect。
3. **打印和离线，与网页同样重要。**
   - 前台工作人员、蓝领工人、刚落地没有流量的人，都更依赖纸和截图。
   - 方案：每张办事卡和"求助"都能一键生成一页 A4 或手机截图尺寸的版本（带二维码和核实日期）。
   - 机构前台可以放一摞按语言分好的单页。
4. **少即是多：现在的选择太多。**
   - 51 个分类、10 个主题、9 个预设，对第一次来的人负担过重。
   - 方案：首屏只保留"我遇到什么事"（搜索 + 4 个最常见入口）和"地图"两件事；分类收进"更多"。
5. **"住在这里"和"刚到这里"是两种使用方式，入口应该分开。**
   - 常住居民、在家工作者、失业人员关心的是"今天去哪、谁能帮我"，不是"落地清单"。
   - 方案：首屏两个并列入口："刚到 Kamloops"和"住在 Kamloops"，内容共用，排序不同。
6. **推广要借别人的渠道，而不是自己发邮件。**
   - 30 封邮件只收到 1 封回复，说明冷邮件效率很低。
   - 方案：
     - 进入机构已有的资源清单：图书馆的社区资源页、Kamloops Connect、TRU 国际学生手册、SD73 新生家庭包；
     - 做一个可以嵌入机构网站的小组件，或者一个"给本机构用的专属链接"。

## 二、分角色意见

### 1. 政府工作人员（Service BC、ICBC、Service Canada 前台）

**他们在意的**：信息错了，读者会把责任算到窗口头上；不能给人"官方背书"的错觉。

| # | 意见 | 方案 | 优先级 / 成本 |
|---|---|---|---|
| 1.1 | 办事卡里的材料清单一旦过期，排队的人会在柜台被拒 | 每张卡显示"对照的官方页面 + 核对日期"（已有）。另外在官方页面变动时提醒维护者：定期抓取来源页、比对内容哈希，有变化就在 validate 里报警 | P0 / M |
| 1.2 | 页面要清楚说明"这不是政府网站" | 页脚已有声明。办事卡顶部再加一行小字："非官方整理，以 [官方链接] 为准" | P0 / S |
| 1.3 | 希望读者来之前就预约好、带齐东西 | 每张卡加"去之前检查"：预约链接、营业时间、文件清单做成可勾选项 | P1 / S |
| 1.4 | 柜台工作人员自己也会用它给人指路 | 做"工作人员模式"：按机构类型整理的一页速查（附近的翻译、食物、住所、法律援助），可以打印贴在柜台后面 | P2 / M |

### 2. 图书馆工作人员（TNRL）

**他们在意的**：图书馆是公认的中立入口，很多新居民第一站就是图书馆；Margo 已经回复并愿意合作。

| # | 意见 | 方案 | 优先级 / 成本 |
|---|---|---|---|
| 2.1 | 馆员每天回答"去哪办 X"，需要一个能指给读者看的东西 | 在图书馆的公共电脑和 iPad 上放书签，或者打印"办事卡合集"作为参考资料 | P1 / S |
| 2.2 | 图书馆自己的活动（ESL 会话、求职、报税诊所、社区通行证）没有被充分展示 | 地点里的图书馆条目链接各分馆页面（已做）；办事卡里提到图书馆能帮忙的地方（报税诊所、上网、打印），都点名具体分馆 | P1 / S |
| 2.3 | 希望数据以 TNRL 官网为准，并能方便地通知更新 | 给 TNRL 一个固定的更正邮箱或表单，承诺 7 天内处理并公开记录 | P0 / S |
| 2.4 | 图书馆可能愿意托管或联合署名 | 长期方案：以"社区合作项目"的名义请图书馆背书。前提是先有维护规则和纠错记录 | P1 / L |
| 2.5 | 公共电脑多人共用，隐私是问题 | "清除本机记录"已有；再在图书馆电脑上默认进入"访客模式"（不存收藏和勾选），用 `?kiosk=1` 触发 | P1 / S |

### 3. 移民中心工作人员（KIS 定居服务、SWIS）

**他们在意的**：不能替代他们，只能帮他们省时间；信息要跟他们的服务资格一致。

| # | 意见 | 方案 | 优先级 / 成本 |
|---|---|---|---|
| 3.1 | 工具不能让人觉得"看网页就够了，不用找定居服务" | 保持"找定居专员"作为第一张卡（已是）；每张卡的"卡住了"出口都指向定居服务（已有），并写清预约方式 | P0 / S |
| 3.2 | 服务资格很复杂（PR、难民、临时居民能用哪些），网页写错会误导 | 增加"我是什么身份 → 我能用什么"对照卡，由 KIS 审核后上线；在审核之前不写 | P1 / M（需要机构参与）|
| 3.3 | 专员希望能把某张卡直接发给客户 | 已有 `?task=` 链接和分享；再加"生成给客户的清单"：选 3–5 张卡，生成一个短链接或一页 PDF，选定语言 | P1 / M |
| 3.4 | 专员面对的语言远不止 6 种（阿拉伯语、旁遮普语、乌克兰语、西班牙语、他加禄语、波斯语等） | 按本地需求扩语言：旁遮普语优先（南亚是本地最大的少数族裔群体），其次阿拉伯语、乌克兰语、他加禄语。先只翻译办事卡和求助面板，不翻全站 | P1 / L |
| 3.5 | 他们有活动、有讲座，但没有地方统一展示 | 做一个"本周活动"板块，数据来自机构提交表单，每条两周后自动过期 | P2 / M |

| 4.3 | 找房最怕被骗 | 新增"安全找房"卡：常见诈骗信号、BC Housing 登记、押金规则、看房清单 | P0 / M |

### 5. 固定居民（常住居民）

**他们在意的**：不需要落地清单，需要"今天能用的"和"遇到事时能找的"。

| # | 意见 | 方案 | 优先级 / 成本 |

| 5.1 | 首页让他们觉得"这不是给我的" | 首屏"住在 Kamloops"入口：现在营业、公交、公园、垃圾回收日、除雪、市政服务、康乐补贴 | P1 / M |
| 5.2 | 市政服务是常住居民最常查的，但现在几乎没有 | 做"城市服务"卡：垃圾与回收日程（链接市政府的查询工具）、除雪规则、报修 311 类服务、房主补助每年申请、选举 | P1 / M |
| 5.3 | 照顾老人、孩子课外、康乐活动 | 已有 eldercare 卡和"住了很多年"一节；再把 ARCH / KamPASS 做成一张独立的办事卡 | P1 / S |

| 5.5 | 他们对"新移民"字样敏感，可能觉得被排除在外 | 继续使用"新居民 / 居民"的措辞（已有规则），避免"移民专用"的观感 | P1 / S |

## 三、按维度汇总

- **两个入口**："刚到"按时间线，"住在这里"按日常需求（P1 / M）。
