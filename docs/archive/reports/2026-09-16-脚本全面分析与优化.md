## 二、会静默出错的

- **六个脚本用相对当前目录的 `'src/data-kamloops.js'`，其中四个还往里写**（`scripts/data/*.py`、`flyers/*.py`、`tests/audit6.py`）。换个目录跑轻则 FileNotFoundError，重则写进另一个同名文件。
- **九处各自手写的 `re.search(r'const P=(\[.*?\]);')`**，三种正则变体（`;\n` / `;` / `;\s*\n`），全都悄悄依赖同一条不成文约定："`];` 只在语句结尾出现"。备注里多一个 `]` 就会静默截错，而且每个变体断的位置还不一样。
- `check-links.py:82` 的 `.lstrip('www.')` 是按**字符集**剥的，不是按前缀：`westsyde.sd73.bc.ca` → `estsyde.sd73.bc.ca`。目前 188 条 URL 恰好两边对称所以没出错判，但差一个 w 开头的域名就会把真跳转判成 OK。
- `check-links.py` 的 `check()` 没兜住 `ValueError` / `InvalidURL` / `UnicodeError`，**一条坏 URL 会让 `ex.map` 抛出、丢掉整轮已跑完的结果**。
- `export-open.py` 写 `build/open-subset.json` 前不 `makedirs`，全新 clone 上直接 FileNotFoundError（和 `build.py` 之前那个是同一类）。
- `monthly-quality-check.sh:35` 把 stderr 折进 stdout，**export-open 一旦抛异常，traceback 的最后一行会被当成"本月过期数"原样写进质量日志**。
- `deploy.sh` 的 `grep -oc` 在 GNU 下数出现次数、BSD/macOS 下数行数——同一条命令两台机器两个结果；`md5 -q` 只有 BSD 有；`/tmp/deploy-idx.html` 是固定路径，curl 失败时会把上一轮的残留当成这次的线上页面读。
- `scripts/data/fixcoords.py:27` 街道键截断到 14 字符，`Trans-Canada Hwy` 和 `Trans-Canada Hwy E` 合成同一条街（当前数据有 9 条落在这个键上），然后拿一条直线去拟合 20 公里、两个方向的公路；而且非幂等，第二遍锚点更少。

## 六、修好 deploy.sh 之后立刻发现的线上问题（2026-09-16）

修好校验闸门、让 `--verify-only` 第一次真正跑完之后，那条以前不可能打印出来的警告出现了，
顺着查下去是一个真问题：

**`worker.js` 的安全头对首页从来没生效过。**

`SECURITY_HEADERS` 写得很完整（CSP、`X-Content-Type-Options`、`X-Frame-Options`、
`Referrer-Policy`、`Permissions-Policy`、COOP），第 107 行也确实对每个响应套上了。
但 `wrangler.toml` 的 `[assets]` 没有配置行为，而 Workers Static Assets 的默认是
**请求命中静态资源就由资源层直接返回，Worker 的 `fetch` 根本不跑**。
`GET /` 命中 `public/index.html` 直接发出去，`withSecurityHeaders` 没机会执行。

这也解释了探针的形状：`/api/event` 和那十个敏感路径都没有对应文件，会进 Worker，
所以全对；唯独首页——真正需要 CSP 的那一个——四个头一个都没有。

线上实测（2026-09-16）：

```
⚠ 首页缺少 content-security-policy
⚠ 首页缺少 x-content-type-options
⚠ 首页缺少 x-frame-options
⚠ 首页缺少 referrer-policy
⚠ 安全头只在 Worker 响应上有，静态首页绕过了 Worker
```

### 改动
- `wrangler.toml` 的 `[assets]` 加 `run_worker_first = true`（wrangler 4.133.0 支持）。
- `deploy.sh` 的安全头检查从只查 CSP 扩成四个头一组，并加了一条对照探测：
  首页没有而 Worker 路径有 → 直接点出是 `[assets]` 的问题。
- `deploy.sh` 的结尾判定：原来 `FAIL` 只统计敏感路径那一组，前面四项警告了不算数，
  于是屏幕上有 ⚠ 结尾还打印"全部检查通过"。改成 `warn()` 自己记账，有任何 ⚠ 就不算通过、以 1 退出。

### 启用 CSP 前做过的核对
这条 CSP 从来没被真正执行过，所以先确认页面没有一直在偷偷违反它：
- 无 `eval` / `new Function`（CSP 没给 `unsafe-eval`）
- 唯一的 `fetch` 目标是 `/api/event`（同源，`connect-src 'self'` 够用）
- 实际用到的瓦片域名只有 `api.maptiler.com` 和 `server.arcgisonline.com`，都在 `img-src` 里
- `manifest.json`、`sw.js`、图标全部同源
- `sw.js:63` `if (url.origin !== self.location.origin) return;` —— Service Worker 明确跳过跨域请求，
  所以给 `sw.js` 加上 `connect-src 'self'` 不会挡住瓦片
- `geolocation=(self)` 与页面的"分享位置"功能一致

结论：这条 CSP 可以安全启用，不需要放宽。
