## 二、日志与埋点检查

### 链路

整条链路是：

`trackEvent()` → `sendBeacon /api/event` → `worker.js` 校验（只收本站来源、每 IP 每分钟 300 条）→ Cloudflare Analytics Engine

- 字段：11 个文本列加 2 个数值列。
- `double2 = 1`：标记维护者流量（`?debug=1` 和部署冒烟事件）。
- 单页上限：250 条。超过后会记一条说明，所以被截断的会话在数据里看得出来。
- 本地缓冲：只在 `?debug=1` 时才写入 localStorage。

### 完整的部分

- **数量**：约 65 种事件，覆盖地图筛选、搜索、地点查看与联系、收藏、分享、办事卡、指南、离线、PWA、JS 报错。
- **隐私处理**：
  - 搜索词会被清洗：去掉 3 位以上的数字，截到 24 字；危机类词一律替换为 `[crisis]`。
  - 从不记录 IP、User-Agent、cookie。
- **维护者流量**：可以单独排除。

### 本轮发现的缺口与处理

| 缺口 | 处理 |
|---|---|
| 办事卡"官方来源 ↗"点击没有记录 | 新增 `task_src {id, to:域名}` |
| 办事卡里其他外链点击没有记录 | 新增 `task_link {id, to}` |
| 指南正文外链点击没有记录 | 新增 `guide_link {to}` |
| "报告错误 / 反馈"邮件链接点击没有记录（数据纠错渠道的使用量完全看不到） | 新增 `feedback_click {kind: place / task / general, id, cat}` |
| 季节提醒只记了关闭和点链接，没有曝光，算不出点击率 | 新增 `season_shown {id}`，每次打开页面最多一条 |
| `help_open` 没有入口字段 | 核查后发现只有一个入口（顶部"求助"按钮），不需要加 |

实现方式：在 capture 阶段挂一个委托监听，只记录目标**域名**，不记录完整 URL，也不记录任何文字。现有的处理函数一个都没改。

### 分析工具的问题（已修）

- **`analyze-events.py` 的事件字典过时**：
  - 其中 `marker_cta`、`clear_filter`、`all_areas`、`lang_switch` 从来没有被发出过。
  - 真实存在的 `cta_click`、`task_*`、`help_open`、`season_*` 等没有列出。
  - 已按代码实际发出的事件重写。
- **"无搜索关键词"检查与实际相反**：`search_run` / `search_empty` 本来就带清洗后的 q，所以每份导出都会被判"有问题"。已改为检查 q **确实被清洗过**，并用正反两份样例验证：清洗过的判为通过，带电话号码的判为不通过。
- **`query-events.py` 缺少常用查询**：新增 6 个预设：
  - `tasks`：办事卡打开次数
  - `taskout`：办事卡"有用 / 卡住了"反馈
  - `links`：外链点击
  - `feedback`：反馈点击
  - `season`：季节提醒
  - `help`：求助面板每日打开次数

  同时补全了 blob4–blob11 的字段说明。新预设都用 Worker 已有的独立列分组，不需要解析 JSON。
  > 新预设的 SQL 没办法在这里连 Cloudflare 实测（需要你的 API token）。第一次运行时如果报错，把错误信息发给我即可。

### 有意不记录的（需要你决定是否改变）

1. **拨打电话**：包括地点电话、办事卡里的电话、求助热线。
   - 危机热线和求助面板里的任何操作，我建议永远不记。"谁打了危机热线"正是这个工具承诺不去知道的事。
   - 如果想知道"办事卡里的电话有没有人打"，可以只记 `task_call {id}`，不记号码。**需要你同意后再加。**
2. **完成了哪张办事卡**：`task_done` 只记总数，隐私说明里承诺了勾选结果只留在设备上。保持不变。
3. **求助面板的"快速离开"和"清除记录"**：刻意不记。保持不变。
