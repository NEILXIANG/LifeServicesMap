# 访问分析方案对比

> 项目上线后想"知道用户怎么用"，需要先想清楚你要的是**访问情况**（聚合、页面级）还是**访问习惯**（个体、用户级）——这两者的技术、合规、价值都不同。

---

## 一、先把"想看的指标"列出来

在选方案之前，先明确**你想看哪些问题**。这决定了工具选型。

| 你想知道什么 | 性质 | 难度 |
|---|---|---|
| 有多少人打开过？什么时候？ | 聚合 | 零代码可实现 |
| 从哪些国家/城市来的？ | 聚合 | 零代码可实现 |
| 哪个时段是高峰？ | 聚合 | 零代码可实现 |
| 有多少人在哪一步走掉（漏斗）？ | 半聚合 | 需要埋点 |
| 用户最常搜的关键词是什么？ | 半聚合 | 需要埋点 |
| 用户点了哪些 marker / 收藏了什么？ | 个体 | 需要后端 + 合规设计 |
| 哪些用户多次访问、停留多久？ | 个体 | 需要用户 ID + 合规设计 |

> 项目定位是新移民生活服务工具，**用户群体隐私敏感**（可能涉及就医、办身份、家庭地址等敏感场景）。建议**只做前 3 类（聚合层）**，把"个体行为"留在本地 `localStorage` 即可，不要上传到服务器。

---

## 二、方案对比（按"零代码"到"完全自建"排序）

| 方案 | 看什么 | 难度 | 费用 | 合规 | 推荐度 |
|---|---|---|---|---|---|
| **A. Cloudflare Workers 内置 Analytics** | 请求数、错误率、状态码、地理位置、CPU 时间 | ⭐ 零代码 | ✅ 免费 7 天留存 | ✅ 不存 PII | ⭐⭐⭐⭐⭐ 首推 |
| **B. Cloudflare Web Analytics** | 页面浏览、加载性能 | ⭐⭐ 插入一行 JS | ✅ 免费 | ✅ 不存 PII | ⭐⭐⭐⭐ |
| **C. Plausible / Umami（自托管）** | 同 B，更细分（事件、漏斗、来源） | ⭐⭐⭐ 插 JS + 后端 | ✅ 自托管免费 / 商业 $9/月起 | ✅ 极隐私友好 | ⭐⭐⭐⭐ |
| **D. Cloudflare Analytics Engine** | 完全自定义事件 | ⭐⭐⭐⭐ 写 Worker | ✅ 免费 100K/天 | ⚠️ 自己保证 | ⭐⭐⭐ |
| **E. Google Analytics 4（GA4）** | 完整漏斗、用户画像 | ⭐⭐ 插 JS | ✅ 但要 consent banner | ❌ cookie + 跨境 + 用户反感 | ⭐ |
| **F. 个体用户行为埋点（自建）** | 每个用户的点击序列 | ⭐⭐⭐⭐⭐ 后端 + 合规 | 视规模 | ❌ PIPEDA/PIPL 合规高 | ⭐ 慎做 |

## 三、推荐组合：方案 A + B（90% 用户够用）

绝大多数"想知道访问情况"的需求，**A + B 就能全覆盖**，且**零合规风险**。

### 方案 A：Cloudflare Workers 内置 Analytics（无需任何代码）

**已经在线了**——你的 `kamloops-lifemap` 项目自带这个能力，去 Dashboard 就能看。

**能看到的指标**：
- 请求数（按小时/天/周）
- 错误率（4xx/5xx 比例）
- 状态码分布
- 子请求数（地图瓦片拉了多少次）
- 地理分布（访问者来自哪些国家/城市）
- 缓存命中率

**怎么看**：
1. https://dash.cloudflare.com/ → 左侧 **Workers & Pages** → 点进 `kamloops-lifemap`
2. 顶部 **Analytics** 标签 → 直接展示
3. 也可以用 GraphQL API 把数据导到自己分析

**限制**：
- 看不到"用户点了哪个按钮"
- 看不到"用户搜索了什么"
- 留存 7 天（Free 计划）/ 30 天（Paid $5/月）

### 方案 B：Cloudflare Web Analytics（一行 JS）

**能看到的额外指标**：
- 页面浏览量（PV）
- 独立访客（UV）
- 加载时间（LCP / FID / CLS）
- 来源（referrer）

**怎么加（10 分钟）**：
1. https://dash.cloudflare.com/ → 左侧 **Web Analytics** → **Add a site**
2. 输入你的 URL：`https://kamloops-lifemap.neilxiang.workers.dev/`
3. Cloudflare 给你一段 `<script>` 代码（beacon.js）
4. 把这段 `<script>` 粘进 `src/engine.html` 的 `<head>` 标签里
5. `python3 build.py` 重建 → 重新部署

**限制**：
- 只看"页面层"行为，看不到应用内部按钮点击
- 仍然**不存 PII、cookie-free**

### 方案 A + B 给你什么、不给你什么

| 指标 | A | B |
|---|---|---|
| 每天有多少人来 | ✅ | ✅ |
| 从哪国/哪城来 | ✅ | ✅ |
| 每天哪个时段是高峰 | ✅ | ✅ |
| 浏览器/设备分布 | ⚠️ 部分 | ✅ |
| 页面加载快不快 | ⚠️ 间接 | ✅ |
| 用户搜了什么关键词 | ❌ | ❌ |
| 用户点了哪个 marker | ❌ | ❌ |
| 用户停留多久 | ❌ | ⚠️ 间接 |

**A + B 不给你看个体行为**——这正是**优点**：项目里用户搜索的内容、收藏的地点可能很敏感，不上传到服务器是最安全的。

## 四、如果你真的想看个体行为（**慎做**）

可能的需求：**想知道"用户最常搜什么词"，以便优化分类和数据**。这其实是个有价值的洞察，但实现起来要谨慎。

### 方案 C：Plausible / Umami（自托管隐私友好方案）

**思路**：用 Cloudflare D1 / Workers KV 存聚合后的搜索词（不上传原始查询字符串），或用一个隐私友好的第三方分析工具。

**Plausible 自托管**：
- Cloudflare Pages 上能跑
- 完全 GDPR / PIPEDA / PIPL 合规
- 免费（自托管）或 $9/月（托管）
- 看不到 PII，只有聚合

**Umami Cloud**：
- 类似 Plausible，更轻量
- 免费层够小项目用

### 方案 D：Cloudflare Analytics Engine（自建、最灵活）

Workers Free 每天 100K 数据点免费，留存 3 个月。如果你想看"用户点了哪个分类按钮"，可以在前端代码里写：
```js
env.ANALYTICS.writeDataPoint({
  blobs: ['cat_click', category, region],
  doubles: [Date.now()],
  indexes: ['anonymized_session_hash'],
});
```
然后用 Workers Analytics Engine 的 SQL 查询接口看聚合。

**风险与代价**：
- 要写 JS 代码 + Worker 后端
- 要在 UI 上明示"我们收集匿名使用数据"
- 任何"PII 风险"的字段（搜索词含地址/姓名等）要**先清洗再上报**

### ❌ 不推荐 GA4
- Cookie 类追踪 → 触发 GDPR consent banner
- 跨境数据传输（Google 服务器在境外）
- 与项目"无 cookie、无追踪"的隐私定位冲突

## 五、合规与隐私边界（**最容易被忽视**）

项目定位（新移民生活服务）决定了用户对隐私的容忍度低。

### ✅ 可以做（无风险）
- Cloudflare 内置 Analytics（看请求数、地理位置）
- Cloudflare Web Analytics（cookie-free 页面浏览）
- 聚合后的搜索词频次（不含原始词）

### ⚠️ 需要明示同意
- 任何"埋点 + 上报"的行为追踪
- 留存搜索历史
- 收藏数据同步到服务器（目前只有 localStorage 是最安全的）

### ❌ 不要做
- 第三方 cookie（GA4、Mixpanel）
- 用户指纹 / 跨设备 ID
- 不告知就收集位置（即使聚合）
- 给用户推送通知前未授权

## 六、推荐落地步骤（**今天能做**）

### 第一步（0 分钟）：去 Cloudflare Dashboard 看一眼 A
你已经有 Workers 内置 Analytics，登录 dashboard 就能看：
- https://dash.cloudflare.com/ → Workers & Pages → kamloops-lifemap → Analytics

**10 分钟后等真实访问者来**，就能看到首批数据。

### 第二步（10 分钟）：加 B
按上文"方案 B：Cloudflare Web Analytics"加 beacon，build & 重新部署。

### 第三步（可选，等数据积累一周后）
看 A + B 数据后，再决定要不要做 C / D。大多数项目 **到这一步就够用了**。

## 七、如果你想了解"用户行为"但又不想上传服务器

**折中方案**：在应用本地 `localStorage` 里加一个**匿名事件队列**，永远不上传——只在你（开发者）调试时按一个"调试按钮"导出 JSON。

代码示意：
```js
// 不上传，只在本地累积
const stats = JSON.parse(localStorage.getItem('kamloopsStats') || '{}');
stats[event] = (stats[event] || 0) + 1;
localStorage.setItem('kamloopsStats', JSON.stringify(stats));
```

这样：
- 你不会让用户反感
- 你也不用担合规问题
- 用户主动愿意的话，可以让你"查看我的使用统计"

## 一句话总结

| 你想问 | 用什么 |
|---|---|
| "有多少人来过？" | **A. Cloudflare 内置 Analytics**（已经在跑了，去 dashboard 看） |
| "页面加载快吗？来自哪些国家？" | **B. Cloudflare Web Analytics**（加一行 JS） |
| "用户最常搜什么？" | **D. Analytics Engine** 或 **C. Plausible**（需要写代码 + 隐私设计） |
| "用户在我不知道的情况下做了什么" | **不要做**——既不必要，也不合规 |

**A 已就绪、零成本**——你部署完的那一刻它就开始记录了。去 Dashboard 看看，等 24 小时后就有首批数据。
