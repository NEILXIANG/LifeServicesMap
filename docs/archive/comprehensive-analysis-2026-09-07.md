## 一、埋点与日志分析

### 1.1 当前架构概览

| 层级 | 实现 | 说明 |
|------|------|------|
| Phase A（服务端） | `navigator.sendBeacon('/api/event', Blob)` → Cloudflare Worker → Analytics Engine | 生产级数据收集 |
| Phase B（本地） | localStorage 环形缓冲区（上限 1000 条） | 供 `?debug=1` 面板使用 |
| Cloudflare Web Analytics | 独立 beacon（token: dfb57b079102488baabcd4523f0fda75） | 匿名页面访问统计 |
| 会话标识 | `crypto.randomUUID()` → localStorage，纯本地生成 | 无 IP / Cookie / 指纹 |

**已追踪事件类型（25+ 调用点）**：

| 领域 | 事件 |
|------|------|
| 搜索/筛选 | `search_run`, `search_empty`, `region_toggle`, `region_select_all`, `category_toggle`, `category_group_toggle`, `category_clear_chip`, `preset_toggle`, `preset_clear_all` |
| 浏览/查看 | `marker_view`, `marker_close`, `panel_open`, `panel_close`, `route_select` |
| 操作 | `cta_click`, `fav_toggle`, `share_open`, `share_click`, `reset_all` |
| 会话 | `session_start`, `lang_change` |
| 异常 | `js_error` |

### 1.2 问题清单

#### 🔴 严重问题

| 编号 | 问题 | 说明 |
|------|------|------|
| E-01 | **隐私声明与实际收集行为矛盾** | 5 种语言的 `privacyNote` 均声称"不收集任何数据"，但 Phase A 实际通过 sendBeacon 向 Worker 发送事件数据。自我诊断报告已标记此为 **#1 信任危机**。需将隐私声明修正为准确描述（"收集匿名使用数据，不收集个人身份信息"）。 |
| E-02 | **缺少漏斗/转化路径追踪** | 无法回答"用户从打开页面到拨打第一个电话/导航到第一个地点"的转化率。缺少 `first_interaction`、`first_cta` 等里程碑事件。 |
| E-03 | **`js_error` 事件缺少上下文** | 仅记录错误存在，不记录 error message、stack trace 或用户当时在做什么（哪个分类/搜索词），难以用于定位问题。 |

#### 🟡 中等问题

| 编号 | 问题 | 说明 |
|------|------|------|
| E-04 | **无指南使用追踪** | 新居民指南（guideCity/guideCA1/guideProv/guideCA2）的打开、滚动深度、关闭均无事件。无法知道指南是否有人看、看到哪里、哪部分最受欢迎。 |
| E-05 | **无会话持续时间度量** | `session_start` 只记录开始，无 `session_end` 或心跳机制。无法计算用户停留时长。`beforeunload` 仅 flush 本地缓冲，不发送结束信号。 |
| E-06 | **搜索质量缺乏深度指标** | `search_run` 记录了查询词和结果数，但缺少：搜索后是否点击了结果（search→view 转化率）、搜索词的语言分布、零结果搜索的后续行为。 |
| E-07 | **缺少设备/浏览器信息** | 事件不携带 device type、OS、screen size 等字段。服务端只能从 User-Agent 推断，但当前 Worker 是否解析 UA 不确定。建议在事件中加入 `device: 'mobile'|'desktop'` 字段（通过 `matchMedia` 判断）。 |
| E-08 | **数据注释（Data Notes）交互无追踪** | 用户打开/关闭数据说明弹窗无事件，无法评估用户是否关注数据来源和免责声明。 |
| E-09 | **公交线路选择无追踪** | `route_select` 存在但需确认是否覆盖了线路切换、面板打开等完整交互链路。 |

#### 🟢 低优先级 / 优化建议

| 编号 | 问题 | 说明 |
|------|------|------|
| E-10 | **环形缓冲区 1000 条上限可能丢失数据** | 高频用户（如维护者测试）可能触发上限导致旧事件被丢弃。当前有 20% 自动清理机制，但无告警。 |
| E-11 | **`_sanitiseQuery` 截断到 24 字符可能丢失有效搜索词** | 中文搜索词如"Thompson Rivers University"恰好 24 字符会被截断。可考虑适当放宽或按语言调整。 |
| E-12 | **缺少离线→在线同步** | Service Worker 缓存页面后用户在离线状态操作，事件存入 localStorage 但无后续同步机制确保上报。 |
| E-13 | **debug 面板无数据可视化** | 当前只显示计数和 Top 8 列表，缺少时间序列图、事件分布饼图等，维护者快速诊断效率有限。 |
| E-14 | **Week 1 数据样本量过小** | 247 请求 / 89 UV 不足以得出统计显著结论。需持续收集至少 4 周再做趋势分析。 |

#### 🟡 翻译质量观察

| 编号 | 观察 | 涉及语言 | 说明 |
|------|------|----------|------|
| L-03 | **敬语/称谓一致性** | es, fr | 西班牙语全文使用 `usted` 形式（"Necesita", "Solicite"），法语使用 `vous` 形式——这是正确的，但需确保未来新增内容保持一致。 |
| L-04 | **分类名称翻译风格** | 全部 | 部分分类名采用直译，部分采用意译。如 `secondhand` → zh"二手店" / en"Secondhand" / fr"Friperies"（更具体，意为"旧货店"）/ ko"중고품"。法语选择了更自然的本地化表达，其他语言偏直译——建议统一策略：要么全部本地化，要么全部直译。 |
| L-05 | **"Newcomer" 的翻译不统一** | 全部 | zh 用"新居民"，ko 用"신규 정착민"（新定居民），fr 用"nouvel arrivant"，es 用"recién llegado"。含义一致但语感不同——"新居民"偏中性，"settled immigrant"偏移民语境。建议确认目标受众偏好。 |
| L-06 | **法律术语翻译** | 全部 | guideProv 法律段落中 "Civil Resolution Tribunal" 各语言翻译方式不同：zh"民事解决法庭"、fr"Tribunal de résolution civile"、es"Tribunal de Resolución Civil"、ko"민사분쟁해결심판원"。韩语翻译最精确（使用了韩国法律体系对应术语），中文最简略。 |
| L-07 | **busFareText 货币格式** | fr | 法语版 `2,25$` 使用逗号小数点（正确法语格式），但 `$` 符号放在数字后面且无空格——标准法语排版应为 `2,25 $`（有空格）。 |
| L-08 | **hint 文本长度差异** | 全部 | 中文 hint 约 80 字符，英文约 120 字符，法语约 130 字符。在小屏设备上，较长的翻译可能导致换行或溢出。需实际测试各语言在 320px 宽度下的显示效果。 |

#### 🟢 低优先级

| 编号 | 问题 | 说明 |
|------|------|------|
| L-09 | **缺少 `hreflang` 标签** | SEO 审计已指出：5 种语言无对应的 `hreflang` 元标签，搜索引擎无法识别多语言版本关系。 |
| L-10 | **PWA manifest 无多语言 `name`** | manifest.json 的 `name` 和 `short_name` 只有英文，安装到主屏时其他语言用户看到英文应用名。 |
| L-11 | **`{CITY}` 占位符在翻译中位置固定** | 某些语言的自然语序可能要求城市名出现在句子不同位置，当前 `tpl()` 只做全局替换无法调整语序。目前 5 种语言的语序恰好都兼容，但扩展新语言时可能出问题。 |
| L-12 | **分类 emoji 跨平台显示差异** | 47 个分类 emoji 在 iOS / Android / Windows / Linux 上渲染效果差异显著（如 🛝 在部分旧系统上不可见）。不影响功能但影响视觉一致性。 |

### 2.4 统一标准建议

| 维度 | 当前状态 | 建议标准 |
|------|----------|----------|
| 专有名词 | 部分保留英文（SIN, MSP, ICBC），部分翻译 | 首次出现写全称+缩写，后续用缩写。政府机构名保留英文原名，括号注翻译 |

### 3.2 行为心理学分析

#### 3.2.1 首次体验的 5 秒法则

用户打开页面后 5 秒内需要回答 3 个问题：
1. **这是什么？** → 标题"{CITY} 生活服务全景地图"可以回答，但"全景地图"概念模糊
2. **对我有什么用？** → 副标题有说明但字号太小
3. **我该怎么开始？** → **完全无引导**——用户面对 260 个标记、47 个分类、7 个区域，无从下手

**优化方向**：增加一个轻量级引导层（非模态），如首次访问时高亮"快捷选择"区域并显示"试试点击下面的按钮"气泡。

#### 3.2.2 选择悖论（Paradox of Choice）

47 个分类 + 7 个区域 + 搜索 + 快捷选择 + 5 个预设 = 超过 60 种筛选入口。心理学研究表明，当选项超过 7±2 时，用户决策质量下降、满意度降低。

**优化方向**：
- 首次访问时只展示 5-7 个最常用分类（"新居民必备"预设已部分实现）
- 将"全部分类"折叠在"更多"按钮后面
- 用场景化入口替代分类列表（"我刚到" → "找房子" → "找学校" → "看医生"）

#### 3.2.3 心智模型错配

| 用户心智模型 | 系统实际模型 | 冲突 |
|-------------|-------------|------|
| "搜索和筛选可以同时用" | 搜索清空筛选，筛选清空搜索 | **互斥设计** |
| "分类是固定的层级结构" | 分类是扁平标签，可多选组合 | 无层级导航（如"餐饮 > 中餐 > 川菜"） |
| "地图上的点就是全部数据" | 地图只显示当前筛选结果 | 用户可能误以为"地图上没看到 = 不存在" |
| "收藏会自动同步" | 收藏仅在 localStorage | 换设备丢失 |
| "指南是独立页面" | 指南嵌在页面底部 | 发现性差 |

#### 3.2.4 认知负荷分析

首次用户需要理解的**新概念**：
1. 区域（Region）— 地理分区
2. 分类（Category）— 功能分区
3. 快捷选择（Quick Picks）— 预设组合
4. 群组（Group）— 分类的上层分组
5. 新居民指南（Guide）— 嵌入式文章
6. 公交线路（Bus Routes）— 独立图层
7. 收藏（Favorites）— 本地持久化
8. 分享（Share）— URL 状态编码
9. 数据说明（Data Notes）— 数据来源与免责声明
10. 隐私（Privacy）— 匿名分析声明

**10 个新概念对首次用户来说过多。** 建议按使用频率分层：首次只暴露 区域 + 分类 + 搜索 + 指南，其余在用户需要时渐进式展示。

### 3.3 优化机会清单

| 优先级 | 优化项 | 预期效果 |
|--------|--------|----------|
| P0 | 首次访问引导（onboarding tooltip 或高亮） | 降低"不知道怎么用"的跳出率 |
| P0 | 搜索/筛选共存（搜索不自动清空分类） | 符合用户直觉，减少操作步骤 |

| P1 | 零结果搜索引导（"试试搜 X？"） | 减少搜索失败的挫败感 |

##### 🔴 高优先级缺口

| G-08 | **歧视应对与权益意识** | 不同肤色/语言的人可能遇到歧视。指南应告知：遇到歧视怎么办、BC Human Rights Tribunal 如何使用、哪些行为构成歧视。当前 guideProv 只列了电话号码，无场景化说明。 | 少数族裔新居民 |

| G-12 | **宗教与信仰场所** | 有 12 个宗教 POI 但指南中无提及。新居民可能想找自己信仰的礼拜场所，或了解本地宗教文化。 | 有宗教信仰的新居民 |

| 租房 | 押金规则 | 补充：如何找房源（Craigslist/Kijiji/Facebook Marketplace）、入住检查清单（condition report）、租客保险 |

### 4.4 内容组织优化

| 问题 | 说明 |
|------|------|
| **缺少"按身份"导航** | 留学生、新移民、难民、随行配偶的需求差异大。当前指南按"主题"组织（SIN/银行/医疗），但用户更自然的思维是"我是留学生，我该做什么"。建议增加按身份的快速入口。 |
| **缺少时间线视图** | "第 1 天做什么 → 第 1 周 → 第 1 个月 → 第 3 个月"——新居民最需要的不是百科全书，而是按时间排序的待办清单。 |
| **缺少与地图 POI 的联动** | 指南提到"银行"但无法直接跳转到地图的银行分类。建议在指南中嵌入 `data-action="filter:bank"` 类属性，点击后直接筛选地图。 |
| **缺少更新机制说明** | 政策经常变化（如 MSP 等待期取消），用户不知道指南是否最新。建议在指南顶部显示最后更新日期，并链接到 CHANGELOG。 |
