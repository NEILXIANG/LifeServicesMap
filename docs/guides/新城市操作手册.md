# 新城市操作手册（BC 省内新城市，类型 A）

> 1.1（2026-10-04）。照着做就能把一座 BC 城市从零做到"可审核的草稿"。原则、标准和理由见
> `docs/guides/新城市扩展方法论与标准.md`；这里只写**做什么、敲什么命令、检查什么**。例子都是 Kelowna（2026-10-03/04）。
> 外省（类型 B）和美国（类型 C）要先建省包 / 国家包，见方法论第三节。

每一步结束都要过三道关：**用户体验、人文关怀、法律**（方法论开头的检查表）。每一步都把发现写进
`docs/reports/<日期>-<城市>扩城迭代日志.md`。

---

## 第 0 步：开工前（半天）

1. 读：知识库入口 `docs/knowledge/README.md`（开工前必读 10 条、经验库、资产清单、提示词），再读上一座城市的迭代日志。
2. 选城打分、确认扩展类型（方法论第三节）。**确认至少一个当地合作方**——没有它，第 9 步的电话核实和上线后的分发都做不下去。
3. 列出这座城市的**官方来源清单**：市政府官网和开放数据门户、周边市镇、区域政府、健康局、学区、图书馆系统、公交运营方的 GTFS。

## 第 1 步：城市画像（1 天；可交给两个调研代理并行）

- 产出 `cities/<id>/PROFILE.md`：人口、移民来源与语言、经济、房租、行政结构、地理、原住民、文化特色、门户、交通、教育、医疗、安置、灾害；
  **每个数字带官方出处和年份**，并和上一座城市对照。原始调研存进 `cities/<id>/import/research/`。
- 最后一节"由此决定"：地点目标、优先类别、要特别做的内容、可以不做的内容、区域划分。
- 检查：有没有一个数字只来自第三方？有就换掉或标出来。

## 第 2 步：骨架（1 小时）

```sh
python3 scripts/new-city.py kelowna --name Kelowna --centre 49.888,-119.496 --span 0.14,0.24
```

- 填 `cities/<id>/data.js` 里所有 `TODO:`：公交网址、学区、安置机构电话、24 小时本地热线（庇护所只给电话，不给地址）、本地危机小组、
  紧急警报登记页、季节提示里的本地链接、搜索示例（`examples: {campus, stop}`）。
- 写 `regions.json`（六语区域名）和 `import/config.json` 的区域锚点（每区 3–5 个点）。
- 城市指南 `guide/<lang>.html`：只写官方能确认的事实；城市名一律写 `{CITY}`，公交写 `{TRANSIT}`，学区写 `{SD}`。
- 检查：`python3 build.py --city <id> && python3 scripts/validate.py --city <id>` —— 草稿状态下只剩"上线完整性"的警告。

## 第 3 步：一级数据导入（半天）

全部可重跑，记录出处，坐标统一走政府地址定位：

```sh
python3 scripts/importers/bc_childcare.py --city <id>                 # 省持牌托儿（含会讲的语言、年龄、CCFRI）
python3 scripts/importers/bc_schools.py   --city <id>                 # 省 K-12 + 学区官网电话（先写 import/<学区>-sites.json）
python3 scripts/importers/arcgis_parks.py --city <id>                 # 市政府公园 / 湖滩 / 遛狗区（字段写在 config.json）
python3 scripts/importers/gtfs_routes.py  --city <id> --gtfs <目录>   # 公交线路与换乘站
```

- 每个导入打印"跳过了什么、为什么"——**逐条看**。Kelowna 在这里发现了：省数据把 4 所中学标成小学、同楼不同机构被误判重复、
  一个区一家托儿都没分到。
- 公交导入后把 `BUS_SOURCE` 和六语 `busCoverage` 写进 `data.js`（`validate.py` 核对线路数）；
  把 `licenceData`（用到的每个开放数据集和许可，六语）写进 `data.js`。

## 第 4–5 步：官网调研（1 天；三个调研代理并行）

- 分三组：**安置、法律、住房、钱**；**医疗与心理健康**；**日常生活与文化**。调研要求（用 `docs/knowledge/prompts/官网调研.md`）：
  只用官网或政府名单；每条回答"新移民关键属性"（谁能用、语言、是否免费、要不要预约、带什么、营业时间原文）；
  备注中英两种、不写金额、不用"新移民"；**边做边写文件**（代理中途卡住也不丢进度）。
- 合并：

```sh
python3 scripts/importers/research_merge.py --city <id> cities/<id>/import/research/R2-*.json
```

  规则：安全相关服务永远独立成点；只有图书馆和校园可以把项目（英语角、国际学生办公室）并进备注；没有官网的商户
  可用市政府营业执照确认（记 `src: opendata`）；地址对不上的不上图，留在 `_held_for_review`。
- 补营业时间：调研代理只抄官网原文，存进 `import/hours.json`：

```sh
python3 scripts/importers/apply_hours.py --city <id> --add hours-out.json
```

  只有完全看得懂的才转换；课程表、仅预约、季节性、复杂礼拜时间留给人。

## 第 6 步：办事卡（半天）

```sh
python3 scripts/importers/tasks_from.py --city <id> --from kamloops --export-missing need.json
```

- 在 `import/task-overrides.json` 里：把每张卡的办事处换成本城市的地点；**把卡片里的本地内容逐条改写**（安置机构、学区入学流程与材料、
  看病、庇护所与食物、长者照护）——每条事实都来自官网（Kelowna：SD23 要先经国际教育办公室处理移民文件）。
- 把 `need.json` 交给翻译代理，结果合回 overrides 再生成。工具会拒绝留有源城市地名、机构名、本地电话的卡片。

**每张卡的本地化要求**（2026-10-04 对比 `cities/kamloops/tasks.json` 和 `cities/kelowna/tasks.json` 实测）：

| 卡 | 通常要改什么 | 为什么 |
|---|---|---|
| sin、msp、licence、bank、doctor、housing、jobloss、legal | 只换办事处（`place`） | 步骤是全国或全省统一的；办事处地址是本地的 |
| tax、deposit | 不用改 | 全国或全省统一，也不指向本地办事处 |
| rights | 换"另外"（`also`）里的本地机构 | 权利是全省统一的，但能帮忙的安置机构是本地的（Kamloops 是 SPOKE 项目，Kelowna 是 KCR） |
| settle | 全部步骤、"可以这样说"（`say`）、来源；办事处 | 安置机构和它的服务是本地的 |
| school | 几乎整张卡重写（步骤、要带的、说明、来源、`also`）；加办事处 | 学区入学流程和材料是本地的（Kelowna：SD23 先经国际教育办公室处理移民文件；有欢迎中心） |
| sick | 全部步骤（Kelowna 从 3 步变 4 步）；办事处 | 诊所体系是本地的（UPCC、免预约诊所、急诊各在哪） |
| eldercare | 第 3 步、"找谁帮忙"（`help`）、来源；去掉了办事处 | 长者照护的入口机构是本地的 |
| hardship | 说明（`note`，庇护所名单）、`also`（食物机构）；办事处 | 庇护所和食物银行是本地的 |
| connect | `also`、来源；办事处 | 英语角和社交活动由本地机构办（Kamloops 是安置机构，Kelowna 是图书馆） |

注意：卡片上省一级的事实（例如 MSP、ICBC 的规定）在一座城市改了，其他从它派生的城市不会自动跟着变，目前也没有检查能发现这种不一致——改了就对派生城市重跑 `scripts/importers/tasks_from.py`。

## 第 7 步：城市专属内容（半天）

- 地标：每区一个，"外地人找得到、而且确实要去的地方"（没车的人多就选换乘站）；`LANDMARK_GLOSS` 六语。
- "落地第一天"：用 GTFS 核实机场或车站到市区的公交，**按星期几分别核实**（Kelowna：2026 年 10–12 月周日没有公交停靠航站楼）。
- 季节提示和紧急警报：用当前的官方渠道（Kelowna 2026 年 4 月换成了 Alertable）。

## 第 8 步：翻译（半天；两三个翻译代理并行）

```sh
python3 scripts/importers/apply_translations.py --city <id> --add translate-*.out.json
```

- 译文单独存在 `import/translations.json`，记录所译的英文；英文改了，旧译文自动失效。
- **翻译也是核对**：Kelowna 翻译时三次发现中英文不一致（药房周日时间、儿童弥撒时间、游乐场年龄限制），都按官方原文改正。

## 第 9 步：独立复核、检查、审核清单、电话核实

**9a 独立复核（约半天，5–6 个代理并行）**：把不是来自政府开放数据的地点分批（安全相关的单独成批），每批 30–45 条，
用 `docs/knowledge/prompts/官网独立复核.md` 交给**没有参与第 4–5 步的**代理。每个代理只用官网和政府页面，逐字段给出
"一致 / 改正 / 无法核实"，边做边写文件。然后：
- 改正写回来源：调研记录改 `import/research/*.json`（备注、时间、电话），手写记录改 `places.json`；营业时间进 `import/hours.json`；
  学校的电话和名称进 `school-phones-cache.json` 和 `config.json` 的 `bc_schools.names`；
- 结果存进 `import/verification.json`（日期、结论、改了什么、留给打电话的人的问题）；
- 复核通过、有官网的 `stub-pending-verify` 改为 `official`；
- 改过英文的备注重新翻译（`apply_translations.py --add`），再把导入连跑两遍。

**9b 自动检查（工具约 1 小时）**

```sh
# 可重跑性：把全部导入连跑两遍，places.json 必须逐字节相同
python3 scripts/consistency_check.py --city <id> --strict   # 各语言的数字、电话一致；没有其他城市的名字
python3 scripts/check-links.py --city <id>                  # MOVED 的改成新网址；BLOCKED 是网站挡机器人，复核时已人工读过
python3 scripts/review_checklist.py --city <id>     # 上线差距 + 按后果排序的审核清单 → docs/reports/
python3 scripts/verify_sheet.py     --city <id>     # 可打印电话核实表（含复核留下的问题）→ 运营资料目录
./scripts/check-all.sh                              # 完整测试：Kamloops 回归 + 每座城市的 tests/<id>/guitest.py
```

**9c 城市界面测试**：复制 `tests/kelowna/guitest.py` 到 `tests/<id>/`，改三处——禁用词表（**参照城市**的地名、电话、票价）、
UPCC 的名字、"附近"测试用的坐标。它在六种语言下打开每个弹窗、每张办事卡、每条公交线路，搜索常用词，检查 320 宽的布局。

- 浏览器里六种语言各打开一次，搜几个本地词（Kelowna：laundry、UPCC、英语角），看办事卡。
- **电话核实由人完成**（合作方、熟人、自己）：核实表上的安全相关地点全部打完，确认的记录改 `src: own`、`v` 改当月；
  改正的内容写回调研文件，再重跑合并。

## 第 10 步：上线（需 Neil 同意）

- 审核清单的上线差距全部 ✅ 后，删掉 `city.json` 的 `"status": "draft"`，`validate.py` 恢复全部硬性规则。
- 在 `wrangler.toml` 加 `[env.<id>]`（模板在文件末尾），`./deploy.sh --city <id> --dry-run` 看设置，**征得同意后**再部署。
- **底图 key 加新域名**：MapTiler 的 key 只对白名单里的网址生效；不加的话新城市会悄悄退到备用底图（不报错）。
  在 MapTiler 后台把 `https://<id>-lifemap.neilxiang.workers.dev` 加进允许来源（只有账户主人能做），部署后确认用的是主底图（L-091）。
  2026-10-04 实测：同一个 key，Kamloops 网址 200，Kelowna 网址 403——Kelowna 上线前必须做。
- **图标和分享预览图**：`app/pwa/icon.svg` 画的是 Kamloops 两河交汇，所有城市共用；上线前给城市换自己的（L-096）。
- `[env.<id>]` 里 `run_worker_first = true` 不能漏，否则首页没有安全头；部署探针会逐项检查（L-092）。
- 分发：合作机构推荐、每个渠道一个 `?src=`，上线当天在统计里确认收得到。

## 第 11 步：维护

- 每月：`scripts/monthly-quality-check.sh <id>`；每季度复核安全相关地点的电话和营业时间；GTFS 每出新版就重跑公交导入。
- 用访问数据补漏：搜了没有结果的词（`search_empty`）进下一轮调研清单。
- 每轮迭代结束：发现登记进知识库（`docs/knowledge/lessons.json`），运行 `python3 scripts/knowledge.py`；从经验库的"待办"里挑几条变成检查。

## Kelowna 实际用时（参考）

每步标题里的用时都是 Kelowna 的会话时间，供估算；调研和翻译由 2–3 个代理并行。

- **快（工具和代理，约 1.5 天会话时间）**：从骨架到 450 个地点、全部六语、17 张办事卡、29 条公交线路、审核清单与核实表——
  其中画像、一级数据约 270 个地点、官网调研约 180 个地点、六语翻译。
- **也快（约半天）**：独立复核 232 条（6 个代理并行）并改回来源；界面测试和一致性检查。
- **慢——剩下的全是人的工作，决定上线时间**：75 个安全相关地点的电话核实、约 30 处复杂营业时间、原住民内容请当地 Nation 审阅、
  找到愿意推荐的当地合作方、上线后的分发。
