> ⚠️ **CF Analytics Engine SQL 限制（写 SQL 前必看）** —— 它的 SQL 方言不是完整 ClickHouse，是阉割版：
>
> | 不能用的写法                                  | 替代方案                              |
> | -------------------------------------- | -------------------------------- |
> | `uniq(col)` / `groupUniqArray(col)`   | `count(DISTINCT col)` ✅          |
> | `UNION ALL`                            | 跑多次查询，脚本里合并（funnel 已这样做）          |
> | 子查询 `(SELECT ...)` 作为列              | 改两次查询；或放弃该列                     |
> | `JSONExtractString(blob3, 'id')` 等所有 JSON 函数 | **常用字段已经是独立列，直接 `GROUP BY blob4~blob11`**（语言/城市/域名/来源/id/分类/动作/版本）；只有这些列之外的键才需要 `GROUP BY blob3` + Python 后处理 |
> | `toString(timestamp)`                  | 直接 `SELECT timestamp`（输出 `2026-09-05 07:21:57`） |
> | `timestamp AS time`（给 timestamp 起别名）       | 别名用别的列；timestamp 列必须原名输出          |
> | `formatDateTime(.. '%M')`              | ⚠ 在 AE 里 `%M` = 月份全名（POSIX 行为），分钟要用 `%i` |
> | `topK()`, `quantile*()`, `uniqExact()` | 没有等价替代，别写                        |
>
> **HTTP 错误码含义**：
> - **403** → token 权限不够（重建：Account | Account Analytics | Read）
> - **422** → SQL 语法/方言不被支持（看错误消息，常是上面列表里的某个）
> - **429** → 频率限制（CF 免费层约 5 请求/分钟，重置窗口约 1 分钟）
>
> **成功响应的样子**（注意：**没有 `success` 字段**！跟 CF REST API 不一样）：
>
> ```json
> { "meta": [...], "data": [{...}], "rows": N }
> ```


### 1.2 字段映射（重要！写 SQL 前必看）

Worker 里 `writeDataPoint` 的实际写法：

```javascript
env.ANALYTICS.writeDataPoint({
  blobs:   [sid, t, propsStr, lang, city, host,
            src, id, cat, kind, ver],   // 11 个字符串列
  doubles: [ts, isDev],                 // 2 个数字列
  indexes: [t],                         // 索引列（加速按类型过滤）
});
```

| SQL 列       | 内容                          | 例子                               |
| ----------- | --------------------------- | -------------------------------- |
| `blob1`     | **sid** 匿名会话 ID（24 字符随机）    | `a3f2e1b9c8d7e6f5a4b3c2d1`       |
| `blob2`     | **t** 事件类型                  | `preset_toggle`                  |
| `blob3`     | **props** JSON 字符串          | `{"id":"health","action":"add"}` |
| `blob4`     | **lang** 界面语言                | `zh`                             |
| `blob5`     | **city** 城市                  | `kamloops`                       |
| `blob6`     | **host** 部署域名                | `kamloops-lifemap.neilxiang.workers.dev` |
| `blob7`     | **src** 来源（传单/分享等）          | `flyer`                          |
| `blob8`     | **id** 地点 id 或卡片 id          | `msp`                            |
| `blob9`     | **cat** 分类                   | `health`                         |
| `blob10`    | **kind** 动作（kind/target/to/mode） | `nav`                        |
| `blob11`    | **ver** 版本号                  | `2026.09.13f`                    |
| `double1`   | 事件时间戳（毫秒）                   | `1788591695581`                  |
| `double2`   | 1 = 维护者流量，0 = 真实用户          | `0`                              |
| `index1`    | 同 `blob2`（索引）               | `preset_toggle`                  |
| `timestamp` | **CF 服务端接收时间**（自动）          | 用它做时间过滤                          |

> ⚠️ **时间过滤一律用 `timestamp`（服务端接收时间）。** `double1` 是客户端声称的事件时间，
> 设备时钟错乱时会偏；按时间分桶的报表请用 `timestamp`，不要用 `double1`。
>
> ⚠️ **`double3` 已经不存在了。** 早先的版本用它标记"时间被服务端校正过"，
> 现在 Worker 只写两个数字列（`doubles: [ts, isDev]`）。任何还在查 `double3` 的 SQL
> 都要删掉那一列，否则报错或恒为空。


### 1.3 立刻跑这 5 条（验证数据 + 拿到第一批洞察）

**① 数据有没有进来？（先跑这条）**

```sql
SELECT
  count()                          AS total_events,
  count(DISTINCT blob1)            AS unique_sessions,
  count(DISTINCT blob2)            AS unique_event_types,
  formatDateTime(min(timestamp), '%Y-%m-%d %H:%i') AS first_seen,
  formatDateTime(max(timestamp), '%Y-%m-%d %H:%i') AS last_seen
FROM kamloops_events
WHERE timestamp > NOW() - INTERVAL '7' DAY
```

> ⚠ 分钟符是 `%i`（不是 `%M` —— AE 里 `%M` 会被当成月份全名 "September"）。

**② 事件类型分布（哪类操作最多）**

```sql
SELECT
  blob2 AS event_type,
  count() AS n,
  count(DISTINCT blob1) AS sessions
FROM kamloops_events
WHERE timestamp > NOW() - INTERVAL '7' DAY
GROUP BY event_type
ORDER BY n DESC
```

> 想算"占全部百分比"？AE 不支持子查询做分母——直接两次查询：
> 先跑 `SELECT count() FROM ... WHERE ...` 拿总数，再算。

**③ 最热门的 preset / 分类（props 里的 id）**

```sql
SELECT
  blob3 AS props,         -- {"id":"health","action":"add"} 整串
  count() AS n
FROM kamloops_events
WHERE blob2 = 'preset_toggle'
  AND timestamp > NOW() - INTERVAL '7' DAY
GROUP BY props
ORDER BY n DESC
LIMIT 20
```

> AE 没有 `JSONExtractString`，所以拿不到拆开的 `id` / `action` 列。
> 推荐用脚本 `./query-events.py presets` —— 内部用 Python 解析 props JSON，结果已经按 id+action 聚合好。

**④ 转化漏斗（搜索 → 看详情 → 真打电话/导航/访问网站）**

```sql
SELECT
  countIf(blob2 = 'search_run')             AS searches,
  countIf(blob2 = 'marker_view')            AS marker_views,
  countIf(blob2 = 'cta_click')              AS cta_clicks,
  count(DISTINCT if(blob2 = 'cta_click', blob1, NULL)) AS users_who_acted
FROM kamloops_events
WHERE timestamp > NOW() - INTERVAL '7' DAY
```

> 用 `if + count(DISTINCT)` 模拟"条件 distinct"。或直接 `./query-events.py funnel`（脚本已实现，更直观）。

**⑤ 内容缺口清单（搜了但 0 结果 → 该补的数据）**

```sql
SELECT
  blob3 AS query_props,
  count() AS n,
  count(DISTINCT blob1) AS users_affected
FROM kamloops_events
WHERE blob2 = 'search_empty'
  AND timestamp > NOW() - INTERVAL '30' DAY
GROUP BY query_props
ORDER BY n DESC
LIMIT 50
```

> **这就是你的数据补全优先级清单** —— 排名越靠前，越该优先补。

### 1.5 2026-09-07 这一轮补齐的字段与事件

补这些之前，有几个问题是**完全查不出来的**，不是查得不准：

| 新增 | 之前的后果 |
|---|---|
| `guide_open` / `guide_close{ms}` | 新居民指南（27 小节、五语言）没有任何打开埋点，"有没有人读指南"无法回答 |
| `note_open` | 数据说明弹窗同上 |
| `session_start.dev`（phone/tablet/desktop） | 无法按设备分组，所有比率都是手机和电脑两个人群的平均值 |
| `session_start.pwa` | manifest 从上线起就带着 `?source=pwa`，但没人读它，"有没有人装到桌面"查不到 |
| `session_start.deep` | 分享链接带来的访问与直接访问混在一起，分享功能的效果无从评估 |
| `marker_view` → `marker_close.ms` | 区分不了"点开看了一眼"和"真的读完了"，除非做 self-join，而同一会话重复打开同一地点时连 self-join 都不成立 |
| `search_run.n` | 搜索成功与失败无法在同一行里判断 |
| `fav_toggle.cat` | 字段名一直写错成 `P[idx].cat`（实际字段是 `c`），所以这一列**从来都是空的**，"大家收藏什么类型"查不出来 |
| ~~`double3`~~ | 当时用它标记时钟被校正过的事件；**该列后来已移除**，现在按时间分桶一律用 `timestamp` |
| `budget_reached` | 单个会话的事件数没有上限，一个反复点筛选的人可以主导整份聚合 |

同时修掉的两个**数据有效性**问题：

1. **搜索词曾经按每次去抖后的按键上报。** 慢速输入 "grocery" 会产生 gro / groc / groce / grocer / grocery 五行，于是"热门搜索词"排行榜实际上是"真实搜索词的前缀"排行榜。现在等输入停稳（1.1 秒）再记一行，回车视为显式提交立即记录。
2. **`search_empty` 上传的是未清洗的原文。** 清洗函数当时是按事件名挂的（只处理 `search_run`），而 `search_empty` 恰恰是那个专门记录"用户打了什么"的事件——电话号码、门牌号会原样上传，和隐私说明写的不一致。现在改成按**字段名**清洗，任何带 `q` 的事件都会先去掉连续数字再截断。

## 七、关键提醒

1. **Analytics Engine 有 5-10 分钟索引延迟** —— 事件 POST 返回 200 = 已写入，但要等几分钟才查得到。别以为数据丢了。
2. **数据是匿名的** —— `sid` 是随机字符串，不含 IP、UA、cookie。你能说"这个用户点了什么"，但永远不知道他是谁。
3. **搜索词已脱敏** —— 客户端发之前就去掉了 ≥3 位数字串并截断到 24 字符，所以 Analytics Engine 里不会有电话/地址。
4. **90 天滚动保留** —— 想长期留存趋势，每月把 §1.4 的"每日趋势"结果抄进 `data/analytics-log.md`。
5. **本机 localStorage 不要当生产数据库** —— 5MB 上限、跨设备不可见、清缓存即丢。它现在只用于调试。
6. **四个数据源互补，不是替代** —— ① 看真实用户，② 调试自己，③ 看流量，④ 存决策。

## 八、常见故障排查

| 现象                                         | 原因                                            | 怎么办                                                              |
| ------------------------------------------ | --------------------------------------------- | ---------------------------------------------------------------- |
| Analytics Engine 查不到数据                     | 索引延迟                                          | 等 5-10 分钟再查                                                      |
| 查到 0 条，但 POST 返回 200                      | 时间过滤太窄                                        | 把 `INTERVAL '1' DAY` 改成 `'7' DAY`                                |
| SQL 报 `unknown function call: UNIQ`         | `uniq()` 不是 AE 方言                            | 改 `count(DISTINCT col)`                                            |
| SQL 报 `unknown function call: JSONEXTRACTSTRING` | AE 不支持 JSON 函数                                | 改 `GROUP BY blob3` + Python 后处理；或直接用 `./query-events.py places` |
| SQL 报 `unsupported query type: ...UNION ALL` | AE 不支持 UNION ALL                               | 拆多次查询（`./query-events.py funnel` 已实现）                            |
| SQL 报 `unsupported expression type: (SELECT` | AE 不支持子查询当列                                    | 改两次查询，或放弃该列                                                     |
| SQL 报 `unable to find type of column: "timestamp"` | `timestamp AS xxx` 或在 ORDER BY 中引用但未在 SELECT | 删掉 AS 别名；timestamp 直接输出                                          |
| `formatDateTime` 输出 `2026-09-05 07:September` | `%M` 在 AE 里是月份全名（POSIX 语义），不是分钟                  | 分钟符改 `%i`                                                        |
| `?debug=1` 没浮窗                             | URL 参数没生效                                      | 确认地址栏是 `.../?debug=1`（问号后面）                                       |
| 本机导出 0 条事件                                 | 刚清过缓存                                         | 操作几下再导出                                                          |
| `/api/event` POST 返回 400                   | payload 非法                                    | 检查 `t` 必须是 `^[a-z_]+$`（小写+下划线）                                  |
| `query-events.py` 报 403                    | token 权限不足                                    | 重建 token，权限选 `Account \| Account Analytics \| Read`，账户选对          |
| `query-events.py` 报"没找到 token"               | 未配置                                           | `echo 'xxx' > ~/.cf_token && chmod 600 ~/.cf_token`               |
| `query-events.py` 报"null" 错误                | 旧脚本错把"无 success 字段"当成失败                         | 升级到最新脚本（HTTP 200 + 有 `meta`/`data` 即视为成功）                          |
| `query-events.py` 报 HTTP 422               | SQL 方言不被 AE 支持                                | 看错误消息对照 §1.1b 限制表                                               |
| `query-events.py` 报 HTTP 429               | 频率限制（CF 免费层约 5 请求/分钟）                          | 改用 `--list` 之外的具体预设（每次只发 1 查），等待 1 分钟重置                          |
| `wrangler tail` 无输出                         | IDE 沙盒 websocket 被拦                          | 在系统 Terminal（非 IDE）里跑                                            |
| `/index.html` 返回 307                        | CF pretty-URL 重定向                              | 正常行为，跟随后就是首页内容                                                  |
| **DELETE /versions/{id} 返 405**              | CF API 不允许用 Token 删 version                    | 改用 DELETE deployment（已能删，200）；version 需 Dashboard 手动清            |
