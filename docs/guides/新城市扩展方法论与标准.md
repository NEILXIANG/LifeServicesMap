# 新城市扩展：方法论与标准

> 版本 0.3（2026-10-03）。以 Kamloops 的实际做法为基准写成，Kelowna 是第一个按它执行的城市；
> Kelowna 做完后修订为 1.0。工具和字段细节见 `docs/guides/DATA-SCHEMA.md`，差异分层见
> `docs/plans/2026-10-03-城市差异建模分析.md`。

---

## 一、六条原则

1. **政府和官方数据优先。** 任何一类数据，只要有政府或官方来源，就先用它；其次是机构自己的网站；
   第三方（地图平台、目录网站）只在前两者都没有时使用，并在记录上标明。（2026-10-03 定为硬性规则）
2. **关乎安全的先做、先核实。** 医疗、危机热线、安置机构、政府办事处，比餐馆和商场重要得多。
3. **不猜。** 找不到可靠来源的字段宁可留空：坐标不可靠就不上地图，营业时间说法不一就不填。
4. **先草稿，后上线。** 新城市一律从草稿开始（`"status": "draft"`），达到上线标准、经过人工核实，才能部署。
5. **先分析城市，再动手。** 任何数据收集之前，先完成城市画像（第六节）：人口、文化、特色、经济、地理、
   交通、教育、医疗、灾害、新移民人群……画像决定这座城市要重点做什么、不需要做什么。不照搬上一座城市的模板。
6. **把上一座城市的经验带过来。** 每座城市做完都更新第七节"经验清单"，下一座城市开工前先读一遍。

## 二、扩城决策与差异化处理

> **一句话：每座城市都有共性，也都是个性化的。** 共性做成可复用的层（引擎、国家包、省包、模板库），一次做好、所有城市共享；
> 个性放在城市自己的数据里（地点、区域、本地服务、文化与历史、城市画像决定的侧重）。判断一项内容属于哪一边：
> 它在别的城市是否同样成立——成立就上移到共享层，不成立就留在城市层。

### 1. 先决定该不该做、先做哪座城市

扩城的真正成本不在上线，而在**维护**：每多一座城市，每月就多一份核查工作。扩城速度要和维护能力相匹配。
候选城市按五项打分（各 1–5 分），写进立项说明：

| 指标 | 看什么 | 数据从哪来 |
|---|---|---|
| 需求 | 每年新到的永久居民、留学生、临时工人数 | 统计局普查、IRCC 数据、高校国际学生规模 |
| 替代品 | 当地是否已有好用的同类工具 | 安置机构、市政府网站 |
| 当地合作方 | 有没有安置机构或熟人愿意核实和推广 | 外联 |
| 数据可得性 | 政府开放数据、公交 GTFS、托儿和学校数据是否齐全 | 开放数据门户 |
| 相似度 | 与已有城市同省、同健康局、同公交运营方，复用率高 | 城市画像 |

### 2. 从人的需求出发，而不是从城市的数据出发

新移民头 90 天要办的事，**大约八成是全省甚至全国一样的**（SIN、健康卡、银行、报税、驾照），**两成是本地的**
（去哪个办事处、哪路车、哪家诊所）。每座城市按三个问题展开：

1. **来的是谁？** 留学生、家庭移民、难民、季节工的比例——决定重点。
2. **他们头 90 天要做什么？** ——对应办事指南卡片，大部分在省一级复用。
3. **在这座城市具体去哪里做？** ——对应地点数据，这是每座城市真正要做的工作。

### 3. 差异分三类，三种处理办法

| 类型 | 例子 | 处理办法 |
|---|---|---|
| **有或没有** | 机场、地铁、轮渡、海滩、本地危机小组、公交 | **可选模块**：数据里有就显示，没有就整块不出现；引擎里不写任何"如果是某城市"的代码（例：没有公交数据时公交入口自动隐藏） |
| **多或少** | 人口 10 万还是 200 万；6 个区还是 40 个区 | **参数**：地点数量目标、区域粒度、上线门槛按规模调整；只有跨量级（上千个地点）才改架构 |
| **性质不同** | 海边与内陆的灾害；文化、原住民历史、产业 | **模板 + 本地内容**：山火、洪水、海啸、严寒等提示做成模板库，城市选用；文化和历史由城市自己写 |

**每个事实放在它成立的最高一层**：国家 → 省 → 健康局/区域 → 市 → 街区。例如健康卡放在省一级，不在每座城市重复。
层级划分见 `docs/plans/2026-10-03-城市差异建模分析.md`。

### 4. 不规则的现实：不追求一开始就全部建模

多个市镇组成的都会区、原住民自治区、跨城市的服务、同一机构分处多个地址、季节性变化、数据缺失——处理原则：

- **第一次遇到**：用文字说明（地点备注、城市指南），不改数据结构。
- **第二、三次遇到**：抽象成正式字段（例如"市镇"：Kelowna 首次遇到，下一座城市再遇到就加 `muni` 字段）。
- **安全相关的例外从一开始就处理好**：危机热线的服务时间、急诊在湖的哪一边、庇护所地址保密等。

不为假想中的大城市提前把系统做复杂；真到大城市时，按差异分析文档里的"大城市之前"清单改造。

### 5. 承认不确定，并让它可见

- 每条数据有**来源等级**（政府数据 / 官网 / 第三方 / 已电话核实）和**核实月份**，页面上看得到。
- 不确定的不放，或明确标"大致位置""营业时间未知"——不假装确定。
- 新城市先是草稿，达到上线标准才发布。
- 上线后用访问数据补漏：用户搜了却没有结果的词（统计里的 `search_empty`），就是缺数据的信号，进入下一轮补充清单。

### 6. 跨省、跨国扩展

> **范围（2026-10-03 Neil 决定）：国家只考虑加拿大和美国，其他国家暂缓。** 下面关于"其他国家"的通用内容只作参考；
> 跨国工作只按美国准备。

**美国与加拿大的异同（为将来的美国城市准备）：**

| 项 | 与加拿大相同 | 与加拿大不同、需要国家包处理 |
|---|---|---|
| 紧急电话、电话格式 | 911；北美 10 位号码（现有电话识别可用） | 没有 811、211 的省级版本，部分州和县有各自的 211 |
| 行政层级 | 国家 → 州（≈省）→ 市 | 多一层"县"（county），很多服务（公共卫生、法院、社会服务）由县提供 |
| 医疗 | — | 没有全民健康卡；要讲医保（雇主保险、Medicaid、市场保险）、社区卫生中心（FQHC）、急诊不得拒诊 |
| 身份与工作 | — | SSN、ITIN、绿卡、工卡；办事机构是 SSA、USCIS、州 DMV |
| 驾照 | 各省/州自管 | 各州 DMV 规定差异很大 |
| 学校 | 学区制 | 学区更多更细；入学材料要求不同 |
| 货币、单位 | — | 美元；英里、华氏度（距离显示要支持英制） |
| 时区、假日 | 有多个时区 | 联邦假日与州假日不同 |
| 官方数据来源 | — | 美国人口普查局（统计、Census Geocoder 地址定位）、各州/县/市开放数据、公交 GTFS 普遍可得 |
| 隐私 | — | 部分州有自己的隐私法（例如加州 CCPA） |
| 语言 | — | 西班牙语通常是最重要的非英语语言；其他语言视城市而定 |


城市之上还有两层：**省**和**国家**。同省加城市只是加数据；跨省要先建"省包"；跨国要先建"国家包"，并且要过法律和语言两关。

**分层目录（目标结构，到触发点时再建，不提前做）：**

```
countries/ca/         国家包：全国指南（SIN、PR、报税）、全国热线（911、988）、电话号码格式、货币、度量单位、
                      全国法定假日、全国数据来源（统计局、全国地址定位）
provinces/ca-bc/      省包：健康卡、驾照、租房法、省级热线（811、211、310-xxxx）、时区、省级假日、冬胎规定、
                      省级数据来源（BC Address Geocoder、托儿地图、学校数据）、办事指南卡片的通用步骤
cities/kelowna/       城市：只放本地内容，声明 "country": "ca", "province": "bc"
```

**引擎里现在属于"国家/省"的写死内容（2026-10-03 扫描）**：全国指南和 BC 指南整章（`guideCA`、`guideProv`）；
"911" 出现 77 次；电话识别按北美 10 位号码和 BC 的 310-xxxx、2-1-1；界面文字里 32 处加元金额；时区 `America/Vancouver`；
公制单位。这些在 BC 内都正确，**跨省或跨国之前必须先搬到对应的包里**。

| 扩展到 | 触发的工作 | 粗略工作量 |
|---|---|---|
| BC 省内新城市 | 城市数据（本方法论第四节流程） | 数周，主要是数据收集和核实 |
| 加拿大其他省 | 建该省的省包：健康卡、驾照、租房、热线、假日、时区（六种语言）；办事指南卡片改写；找该省的官方数据来源（地址定位、托儿、学校） | 省包 2–4 周 + 城市数据 |
| 美国（其他国家暂缓） | 建国家包：移民制度和办事流程完全不同；紧急电话、电话格式、货币、地址格式、日期和单位；隐私法（欧盟 GDPR 等）与统计同意；数据许可证；界面语言集合可能要变（例如阿拉伯语从右到左）；需要当地的移民专业人士审核内容 | 数月，且必须有当地合作方 |

**跨国的非技术门槛（比技术更难）：**
- **法律责任**：移民和法律类内容答错的代价很高，必须有熟悉当地制度的人审核。
- **隐私**：访问统计在有些国家需要事先征得同意；数据存放地点可能有要求。
- **数据许可**：每个来源的使用条件不同（例如 BC 省开放数据要求按 Open Government Licence – BC 注明出处）。
- **语言**：服务对象的语言由当地新移民构成决定，不一定是现在这六种。

**现在就要遵守的规则（成本为零，避免以后返工）**：
- 新写的引擎代码，**不再加入任何国家或省份的事实**。电话号码、金额、热线、法规一律放进数据层，引擎只负责显示。
- 新城市的 `city.json` 写明 `country` 和 `province`。
- 需要省级内容时，先查省包里有没有；BC 的内容暂时还在引擎里，第一个外省城市之前搬出来（见 `docs/plans/2026-10-03-城市差异建模分析.md` 的实施顺序）。

## 三、数据来源分级

**开工前先列出这座城市的官方来源清单**（写进 PROFILE.md）：市政府官网和开放数据门户（例如 kamloops.ca、kelowna.ca、
opendata.kelowna.ca）、周边市镇和区域政府、省政府数据目录（catalogue.data.gov.bc.ca）、健康局、公交运营方、学区、图书馆系统。
数据从这张清单开始找。

| 级别 | 来源 | 例子（BC 省） | 记录上的 `src` |
|---|---|---|---|
| 一级 | 政府开放数据、政府官方接口 | BC Address Geocoder（地址定位）、Child Care Map（持牌托儿）、K–12 学校位置数据、BC Transit GTFS（公交）、市政府开放数据门户（公园、设施） | `opendata` |
| 二级 | 机构自己的官网 | Interior Health 各院区页面、Service BC 办事处页面、学区和图书馆官网、机构自己的联系页 | `official`（必须附 `w` 网址） |
| 三级 | 第三方 | OpenStreetMap、地图平台、目录网站 | `places`，坐标不确定时加 `precision: low` |
| 核实 | 本人电话或到场确认 | — | `own`，并更新 `v` |

**每个字段都按这个顺序取值。** 例如一家诊所：名称、地址、电话取它自己的官网（二级）；坐标取 BC Address Geocoder（一级）；
都没有时才考虑第三方，并标出来。

**坐标规则**（沿用 Kamloops 2026-09-24 托儿数据的做法）：
- 用 BC Address Geocoder 按地址定位，得分 ≥ 95 才直接采用。
- 数据集自带坐标的，与 Geocoder 的结果相差 150 米以内，才算一致。
- 否则标 `precision: low`（页面会说"大致位置"）。
- 两种来源都不可靠时，不上地图，写进审核清单。

**用官方数据核实第三方来源**：市政府的营业执照数据（例如 Kelowna 的 Business Licences，约 1.3 万条，带地址和行业类别）
用的是公司注册名，不能直接当地点导入，但可以用来确认"这家店确实在这个地址合法营业"。第三方来源的商户能在执照数据里对上的，
可信度高一级。

**营业时间规则**：只采用机构官网明确写出的时间；各来源不一致时不填，页面显示"营业时间未知"。

## 四、流程（每一步的产出）

| 步骤 | 做什么 | 产出 |
|---|---|---|
| 0 立项 | 为什么做这座城市；有没有当地合作方或熟人能帮忙核实 | 计划文档里的一段说明 |
| 1 城市画像 | 按第六节模板，用官方来源（统计局普查、市政府、经济发展机构、CMHC、气象局）分析人口、文化、特色、经济等；对照上一座城市写出"这里有什么不同"；据此定出数据计划和上线目标 | `cities/<city>/PROFILE.md`（每个数字带来源和年份） |
| 2 骨架 | `scripts/new-city.py` 生成目录；填城市设置（公交、学区、热线、季节、警报） | 能构建、能打开的草稿 |
| 3 一级数据导入 | 托儿、学校、公交、市政设施等，用政府数据批量导入 | `cities/<city>/import/` 下的导入脚本，可重跑 |
| 4 安全相关地点 | 医院、紧急诊所、免预约诊所、药房、危机热线、安置机构、政府办事处、食物银行、法律援助 | 每条都有官网来源 |
| 5 日常地点 | 超市、银行、图书馆、社区中心、公园、交通、宗教场所等 | 覆盖第四节的分类要求 |
| 6 办事指南卡片 | 省级通用步骤沿用，本地办事处换成这座城市的，逐张核对来源 | `tasks.json` 和核对日期 `tasksChecked` |
| 7 城市指南与季节提示 | 六种语言；只写已确认的事实，城市名一律用 `{CITY}` | `guide/*.html`、季节提示 |
| 8 翻译 | 地点备注补齐六种语言 | 校验通过 |
| 9 质量检查 | 自动校验、链接检查、抽查 ≥ 10% 的记录与来源一致、安全相关地点电话核实 | 审核清单 `docs/reports/` |
| 10 上线 | 去掉草稿状态，所有规则变为硬性要求；征得同意后按 D1 新建 Worker 部署 | 线上网址 |
| 11 维护 | 每月数据质量检查（过期记录、失效链接）；用户反馈 | `data/data-quality-log.md` |

## 五、上线标准

去掉 `"status": "draft"` 之前，必须全部满足：

**安全相关（全部必须）**
- 医院急诊、所有紧急与初级护理中心（UPCC）、至少 2 家免预约诊所、至少 1 家晚间营业的药房；
- 安置机构、Service BC、Service Canada、驾照办事处、食物银行、免费法律帮助；
- 24 小时热线、本地危机小组（如有）、紧急警报登记方式；
- 以上全部：官网来源 + 电话核实（`src: own` 或核实记录）+ 坐标不是"大致位置"。

**覆盖面**
- 地点数量与人口相称：参考 Kamloops（约 10 万人，387 个地点），按人口和城市特点调整，在 PROFILE.md 里写明目标。
- Kamloops 有的分类，这座城市如果存在，就要收录；不存在的（例如没有海滩）在 PROFILE.md 里说明。
- 每个区域都有地点，并且不能明显少于其他区域。
- 每个主题至少有一个地点（否则主题按钮会显示 0）。

**质量**
- 六种语言全部完成（地点备注、城市指南、季节提示、本地热线）。
- 有营业时间的地点比例不低于 Kamloops（约 60%，露天场所除外）。
- 标为"大致位置"的地点不超过 10%，且不包括任何安全相关地点。
- 办事指南卡片：每张都核对过官方来源，`tasksChecked` 是核对日期。
- 公交：如城市有公交，线路和站点全部来自运营方 GTFS，并写明数据版本（`BUS_SOURCE`）。
- `validate.py` 在非草稿状态下零失败；链接检查没有失效链接；浏览器测试通过。

## 六、城市画像模板（PROFILE.md）

每座新城市先填这张表，再开始收集数据：

| 项 | 要回答的问题 | 影响什么 |
|---|---|---|
| 人口与规模 | 市区和都会区人口；增长快不快 | 地点数量目标、区域划分粒度 |
| 行政结构 | 一个市还是多个市镇；原住民保留地或自治区 | 区域划分、按市镇区分的服务 |
| 地理 | 河、湖、海、山；城市形状；桥和渡轮 | 区域说明、通勤提示、地图初始范围 |
| 原住民土地与历史 | 谁的传统领地；当地需要知道的历史 | 城市指南 |
| 文化与城市特色 | 这座城市以什么闻名（湖、酒庄、大学城、铁路……）；文化区、博物馆、节庆；各族裔社区的历史 | 城市指南、"历史""文化""娱乐"主题、地标 |
| 经济 | 主要产业和雇主、失业率、季节性用工（农业、旅游） | 求职任务卡、WorkBC 等就业资源的分量 |
| 门户设施 | 机场规模、火车站、长途车站 | "落地第一天"内容 |
| 公共交通 | 运营方、线路规模、快线/轻轨/轮渡、票务方式 | 公交数据、交通说明 |
