# Data schema

Everything city-specific lives in one folder: `cities/<city>/`. The engine (`app/engine/`) contains no facts about any
particular city — `validate.py` fails if a local phone number or any city's place id appears in it. A new city starts from
`scripts/new-city.py`; the step-by-step process is `docs/guides/新城市操作手册.md`.

Run `./scripts/check-all.sh --quick` after every edit (build, `validate.py` for every city, cross-language consistency,
knowledge-base check). It checks most of what follows mechanically.

> 2026-10-04: brought up to date with the code (city settings, city texts, `city.json` deploy block, `import/` files,
> required place fields, validator rules). Each table below was checked against the code that reads it.

## The files in a city folder

| File | Holds | Edit by hand? |
|---|---|---|
| `city.json` | Build- and deploy-time settings (below). `"status": "draft"` while a city is being compiled | yes |
| `data.js` | The hand-written part: `CITY`, `BUS_SOURCE`, `LANDMARK_GLOSS`, `FAV_MIGRATE`, and the per-language **city texts** (`UI.<lang>.busCoverage`, `licenceData`, …). The big blocks are pulled in by `/*@json file*/` and `/*@text file*/` | yes |
| `places.json` | `P` — checked against `schemas/place.schema.json` | via the importers or `kamdata.save('P', …)` |
| `regions.json` `bus-routes.json` `tasks.json` `quarantine.json` `landmarks.json` | `RI`, `BR`, `TASKS`, `QUARANTINE`, `LANDMARKS` | yes (Kelowna: generated by the importers) |
| `guide/<lang>.html` | `UI.<lang>.guideCity`, the "About this city" part of the guide, one file per language | yes |
| `PROFILE.md` | The city profile (methodology §4): population, people, economy, place, services, and what follows for the guide | yes |
| `import/` | Importer settings and records (below). Not read by the build | via the importers |

The JSON files are stored indented (one field per line, so a diff shows exactly what changed); `build.py` compacts them.
`kamdata.data_text()` returns the expanded data exactly as the page receives it.

## `city.json`

| Key | Meaning |
|---|---|
| `id` | City id; must equal the folder name |
| `country`, `province` | `"ca"`, `"bc"`. Not read by the engine yet; `validate.py` uses `province` to compare the city with `provinces/<province>/province.json` (below) |
| `status` | `"draft"`: launch-readiness rules in `validate.py` only warn, `check-all.sh` runs the consistency check `--strict`, `deploy.sh` refuses to deploy, the review checklist reports it. Delete the line to go live |
| `title`, `description`, `siteUrl` | Page title and description (`head.html`, manifest); `siteUrl` is also where `deploy.sh` probes |
| `storagePrefix` | Prefix of every localStorage key (favourites, language, task ticks, `sid`, debug events). **Never change it for a live city** |
| `searchStopwords` | Words ignored when matching stop and place names (`["kamloops","bc"]`) |
| `validate.minPlaces` | Floor for the number of places (default 1) |
| `validate.areaCodes` | Optional: the local area codes `consistency_check.py` accepts (default: BC's 250/778/236/604/672; toll-free always accepted). Needed for a city outside BC |
| `review.targetPlaces`, `review.reference` | Read by `review_checklist.py`: the place target decided in PROFILE.md, and the reference city for category coverage and hours share (default kamloops) |
| `review.guiQueries` | Extra searches the city's GUI test (`tests/city_guitest.py`) expects to find places for — words only this city has (a campus, an area, a place of worship) |
| `leakMarkers` | This city's facts that no derived fingerprint catches (campus abbreviation, school district code, fare, Indigenous names). Together with the derived ones (`kamdata.fingerprint`: area names, landmarks, UPCCs, local phones, `CITY.examples`) they must never appear on another city's page — checked by `tests/city_guitest.py --city <id>` and `new-city.py` |
| `leakAllow` | Words another city's fingerprint has that are genuinely also here (Kelowna: "Aberdeen", a school) |
| `timezone` | Optional; `kamdata.today()` uses it (default America/Vancouver). The engine still has its own `CITY_TZ` |
| `deploy.worker` | Cloudflare Worker name (= the `*.workers.dev` prefix) |
| `deploy.wranglerEnv` | `wrangler --env` name; `""` = the top-level config (Kamloops) |
| `deploy.assetsDir` | Deploy folder: `public` (Kamloops, committed) or `deploy/<id>` (built). `build.py` writes `index.html` and the PWA files there |
| `deploy.basePath`, `deploy.swCache`, `deploy.pwaLabel`, `deploy.pwaDescription` | Filled into `app/pwa/` (`sw.js`, `manifest.json`). Bump `swCache` when the cached static assets change |

A city without a `deploy` block (the test city) only builds `build/<id>.html`. `_comment` keys are ignored everywhere.
`build.py` strips `validate`, `review`, `leakMarkers`, `leakAllow`, `timezone`, `status` and `deploy` before the rest reaches the page.

## `provinces/<province>/province.json` — settings every city in a province shares

2026-10-04. Holidays, hotlines, the 2-1-1 line and the winter-driving notice were identical copies in two cities' `data.js`.
Since 2026-10-05 the folder is also a **build input**: `build.py` injects `timezone` and `guide/<lang>.html` (the guide's province chapter — health card, licence, tenancy) as `PROVINCE`; the engine holds no province facts, and `validate.py` fails if it does. The shared values below are still read from each city's `data.js`; this file is the reference, and `validate.py` fails when a city differs:
`holidays` (generate with `python3 scripts/holidays.py`; `--apply` writes them into every city of the province), `hotlines`,
`helpInfo` (= `CITY.help.info`), and `seasons` — each listed notice must exist in the city with the same `text`, dates and icon
and must keep every provincial link (the city adds its own local links, such as its emergency-alert sign-up).
A city in another province needs its own `provinces/<code>/`: `province.json` (timezone, holidays, hotlines, helpInfo, seasons) and `guide/<lang>.html` in all six languages (lesson L-040).

## `CITY`

| Key | Example (Kamloops) | Meaning |
|---|---|---|
| `key` | `'kamloops'` | City id in URLs (`?city=`), share links, calendar files and the analytics `city` column |
| `name`, `prov` | `{zh:'…',en:'…',…}` | City and province names per language → `{CITY}`, `{PROV}` |
| `country` | `'CA'` | Recorded; not read yet |
| `centre`, `zoom` | `[50.684,-120.35]`, `12` | Opening and reset view |
| `bounds` | `[[50.5,-120.7],[50.9,-120.0]]` | `validate.py` rejects places outside |
| `navSuffix` | `', Kamloops, BC'` | Appended when handing an address to a maps app |
| `transit` | `{name:'BC Transit', url:'…'}` | → `{TRANSIT}`, `{TRANSIT_URL}` |
| `examples` | `{campus:'TRU', stop:'Lansdowne'}` | → `{CAMPUS}`, `{STOP}` in the search prompts and the bus-stop hint. Without `campus` the "bus to campus" suggestion is hidden; `stop` is required when the city has routes |
| `schoolDistrict` | `{name:'SD73', url:'…'}` | → `{SD}`, `{SD_URL}` (the catchment finder) |
| `contact_r` | `'moc.liamtoh@…'` | Feedback address, **stored reversed** so no e-mail-shaped string is in the page → `{CONTACT}` |
| `tasksChecked` | `'2026-09-08'` | Day the task cards were last read against their sources (card footer); `validate.py` fails if it is missing or more than 60 days behind `DATA_VERSION` |
| `police` | `'250-828-3000'` | Local police non-emergency line → `{POLICE}`, `{POLICE_TEL}` (footer, Key Numbers). Required (a warning for a draft) |
| `upcc` | `['b29c9af7']` | Place ids of the urgent and primary care centres listed in the health answer under the search box; each must be a `hospital` place. Several are listed with their own open/closed state; empty = the answer shows 8-1-1, pharmacists and 911 only |
| `tiles` | `{url, attribution, …, fallback:{…}}` | Map imagery with an automatic fallback (Esri when absent). The host must be allowed in `worker.js`; OpenStreetMap's volunteer tiles are refused |
| `keyStop` | `/exch\|station\|terminal/i` | Stop names whose labels are always shown |
| `openAir` | `['park','trail','beach','dogpark','splash']` | Categories where no hours means "hours posted on site" |
| `holidays` | `['2026-09-07', …]` | Statutory holidays (ISO dates, sorted); "open now" does not trust weekday hours on them; `validate.py` warns before the list runs out |
| `seasons` | `[{id, from:'MM-DD', to, icon, text:{…6}, links:[{u, t:{…6}}]}]` | One-line seasonal reminder on the map (winter tires, wildfire), dismissible per season and year |
| `help` | `{settle:'778-470-6101', info:'211'}` | Settlement agency line and 2-1-1 in the Help sheet and the cards |
| `hotlines` | `[{n:'911', t:'emergency'}, …]` | Province-wide 24-hour lines; `t` picks the label `UI.<lang>.hot_<t>` |
| `localLines` | `[{n, sms?, note:{…6}}]` | Local 24-hour lines (shelters, crisis lines) — Help sheet and crisis searches. A shelter is a phone number here, never an address. `sms`: a number that also takes texts, written exactly as it appears in the note — it becomes a tap-to-text link (2026-10-19) |
| `localCrisis` | `{n, src, note:{…6}}` or `null` | Local non-police crisis team (not 24 hours) |

## City texts (per-language, in `data.js`)

The engine has a true, generic default for each; a city overrides it with `UI.<lang>.<key>='…';` in all six languages.

| Key | Where it shows | Required |
|---|---|---|
| `guideCity` | "About this city" part of the guide (from `guide/<lang>.html` via `/*@text*/`) | yes |
| `busCoverage` | Bus panel coverage note | when the city has routes — and it must state the route count |
| `busFareText` | Fare line in each route card | when the city has routes (the default only points to the operator) |
| `licenceData` | Open-data attribution under Licence | when any place is `opendata` or the city has routes (the default is empty) |
| `noteCoverage` | Coverage paragraph of the data note → `{NOTE_COVERAGE}` | no — but say where this city's data comes from |
| `noteThirdParty` | Third-party terms sentence → `{NOTE_THIRDPARTY}` | no — Kamloops names Google Places here |
| `legalLocal` | Local legal aid office and clinic in the BC guide → `{LEGAL_LOCAL}` | no |
| `hcUpcc` | Lead sentence of the urgent-care list in the health answer | no |

**Placeholders.** Translated copy must not contain the city name, the transit agency or the school district literally;
write `{CITY}`, `{PROV}`, `{TRANSIT}`, `{TRANSIT_URL}`, `{SD}`, `{SD_URL}`, `{CAMPUS}`, `{STOP}`, `{POLICE}`, `{POLICE_TEL}`,
`{CONTACT}`, `{DATE}`, `{VER}`, `{LIC}`, `{LIC_URL}`. `tpl()` fills them (and the three city-text slots above).
`validate.py` fails if the city's own name, transit agency or school district appears literally; another city's names are
caught by `scripts/consistency_check.py` and each city's GUI test.

## `P` — places

One object per place. Nine fields are required (`schemas/place.schema.json`).

### Required

| Field | Type | Notes |
|---|---|---|
| `id` | string | Stable id, 7–8 lowercase letters or digits. **Never change it**: favourites are stored against it. Importers derive it from the source and key |
| `n` | string | Official name. Must be unique. Avoid parentheticals in a language most readers can't read — use `tag` instead |
| `c` | string | Category key — must exist in `CI` |
| `g` | string | Area key — must exist in `RI` |
| `lat` `lng` | number | Must fall inside `CITY.bounds` |
| `a` | string | Street address. If there is no civic number, navigation falls back to the coordinates |
| `src` | string | Where the facts come from — see `src` below |
| `v` | `YYYY-MM` | When this record was last checked — only change it after checking this record |

### Optional

| Field | Type | Notes |
|---|---|---|
| `p` | string | Phone. Digits in `NNN-NNN-NNNN` form become a tap-to-call link. No email here. |
| `pq` | key | Qualifier for the phone, e.g. `pCity`, `pNational`. Defined in the engine. |
| `e` | string | Email, if the place publishes one. |
| `w` | string | Website, `https://…`. |
| `h` | object | Opening hours — see below. Omit when genuinely unknown, **and always omit for open-air places**: the engine then renders "hours posted on site", which is true without anyone having to know the bylaw. |
| `note` | `{zh,en,fr,es,ko,ja}` | Your own description. **`zh` and `en` are required.** `fr`/`es`/`ko`/`ja` are optional but all-or-nothing: a note with French and no Korean is rejected, because one language silently showing another's text while its neighbours are translated is worse than a clean fallback. |
| `tag` | key | Short qualifier shown as a chip, e.g. `tKorean`, `t24h`. Defined in the engine. |
| `t` | array | **Themes** — the overlapping second axis. See below. Order must follow `TORDER`. |
| `precision` | `'low'` | The coordinate is approximate (roughly ±100 m): interpolated, or published only to three decimals. The popup says so, so the pin never claims a confidence it doesn't have. The address is unaffected, and navigation uses the address. |
| `sameComplex` | array of ids | Other records at the same address or in the same building. Must be **symmetric** — every id you list must list you back. The popup names them, so two markers on one coordinate read as "the postal counter is inside that pharmacy" rather than as duplicate data. |
| `alias` | array | Extra search words (other spellings, acronyms, Chinese names). Programmes folded into a library or campus are added here |
| `pick` | integer | "Our pick" chip (replaced the old ⭐ name prefix) |

### `src` — provenance (required in practice)

Where this record's **factual** fields come from. It does not describe the note —
the note is always the compiler's own writing.

| Value | Means | Validator requires |
|---|---|---|
| `official` | The operator's or governing body's own website is on file, so a reader can check the details at the source | a `w` field |
| `opendata` | Taken from a government open-data set (e.g. the city's GIS / BC Data Catalogue) | the city's `licenceData` attribution |
| `places` | No authoritative source on file; the details rest on third-party map data | — |
| `own` | Checked in person or by phone by the compiler | — |
| `stub-pending-verify` | The details come from an official or first-party page but nobody has yet stood at the door or dialled the number | — |

The Kamloops set was seeded by one mechanical rule — **has `w` → `official`, else
`places`** — because there is no honest way to reconstruct, after the fact, which of
250 records was cross-checked on an official site. So `official` is defined by
something a reader can verify (there is a source of record, and here is the link)
rather than by an unfalsifiable claim about how the data was gathered. Promote a
record to `own` when you actually check it, and add a `w` when you find one.

**Desk checks (2026-10-04).** A record's `src` says where its facts come from; whether a *second, independent
reader* has compared it with that source is recorded separately, in `cities/<city>/import/verification.json`
(`{id: {checked, method: "desk", result: confirmed|corrected, fixed: [...], urls, remarks}}`). A desk check is not a
phone check: it never makes a record `own`. It is what promotes a `stub-pending-verify` record that has a `w` to
`official`, and its `remarks` are printed on the phone-verification sheet as the questions still to ask.

Two things depend on this field:

- the small source chip in each popup, so credibility is visible per record instead
  of only in a blanket disclaimer
- `export-open.py`, which writes out the `official` + `own` subset — the part you
  can hand to a library or another city without inheriting a third party's terms

### `t` — themes, the overlapping axis

A place has exactly **one** category — it decides the pin's colour and icon, so it
cannot be a list — and **any number** of themes. That single-valued category is what
made the map hard to browse for anything but an errand: a library is filed under
`library`, yet it is also a free afternoon with a toddler, a warm room in February,
somewhere to study and a cultural venue. Themes say that out loud without touching
the category system or the map's colour language.

The ten theme keys, their labels, icons and reading order (`TI`, `TIC`, `TORDER`)
live in the **engine**, not here: they are city-agnostic, and another city reuses
them unchanged while only its records' `t` arrays differ.

```js
{ n:'…', c:'library', …, t:['family','culture','free','multi','student','indoor'] }
```

Rules `validate.py` enforces: every key exists in `TI`; no duplicates within a
record; the array is in `TORDER` order; every theme has at least one place (a chip
that can only ever show `(0)` is a wasted tap); and it warns when a theme has five
or fewer, or when more than 40% of records carry no theme at all.

Assignment is scripted, not hand-entered. For imported records the importers set themes from the category
(`CAT_THEMES` in `scripts/importers/research_merge.py`, and each government-data importer). Kamloops' themes were assigned
once by a script now archived at `docs/archive/scripts/themes-2026-09-10.py` (it no longer runs). Either way, `scenic` and
`history` are never inferred from a category alone — "it is a park" is not evidence that it has a view — and a
per-record addition must name the evidence in that record's own verified note.

Filtering is **AND**: ticking two themes means both. That is the only reading under
which adding a chip can never grow the result set, which is the same promise the
area and category filters make, and the useful queries are conjunctions — "free
AND indoor" on a wet Tuesday.

### `h` — opening hours

Structured, not prose, so all six languages render from one source and closed
days can be stated rather than implied.

```js
h:{ a:true }                                  // open 24 hours — a gas station or a
                                              // hospital, never a park
h:{ r:[[1,5,510,1230,0]] }                    // Mon–Fri 08:30–20:30
h:{ r:[[1,5,420,990,0]], q:'qOffice' }        // …with a qualifier
h:{ s:[[7,600]] }                             // a service at Sunday 10:00
h:{ k:'hCall' }                               // a keyed message: "call to confirm"
h:{ r:[[1,7,600,1260,1]], se:'winter' }       // seasonal, approximate closing
```

`r` entries are `[dayFrom, dayTo, openMinute, closeMinute, approx]`, days `1`=Monday
to `7`=Sunday, minutes from midnight. `approx:1` renders as "about". A close time
past midnight is written as `>1440`. Days not covered by any range are rendered as
explicitly closed.

Keys for `k` and `q` (`hCall`, `hCallDay`, `hSite`, `qOffice`, …) are defined in the
engine so they translate; add new ones there, in all six languages.

## `BR` — bus routes

```js
"1":{ n:'Tranquille', co:'#e8710a',
      f:'05:56', l:'26:09',          // first and last trip; >24h means after midnight
      s:[['Stop name',lat,lng], …],  // stops in order
      p:[[lat,lng], …] }             // polyline geometry
```

Derived from the local transit agency's GTFS feed. If a route is omitted, say so in
`busCoverage` rather than leaving a silent gap in the numbering.

## `LANDMARKS` — persistent map labels (optional)

Someone who has never seen the city has no anchor point when the opening view shows
only cluster-count bubbles — the map reads as an abstract grid of numbers rather
than a place. `LANDMARKS` fixes that by naming a handful of well-known places right
on the map, always on, before anyone has clicked anything.

```js
const LANDMARKS=/*@json landmarks.json*/;      // landmarks.json: ["1e3e329a","8fef0c70", …] (Kamloops)
const LANDMARK_GLOSS={"98f81277":{zh:"市中心公交总站",fr:"…",es:"…",ko:"…",ja:"…"}};   // optional second line
```

An array of existing `P` ids. `LANDMARK_GLOSS` adds a smaller second line under a label in the other languages (the
English label is the place name). Each one renders as a
small permanent text label (no separate pin; the place's own marker is unaffected)
using the same anti-overlap placement algorithm as bus-stop labels, so a landmark
label never collides with a stop label, another landmark label, or a visible
cluster bubble. Labels hide themselves at zoom levels or pan positions where they'd
crowd the view, exactly like stop labels already do.

Guidance for choosing ids: one per area, a place someone who does not know the city can find **and actually has to go
to** — a hospital, a library, a bus exchange (most people arriving have no car), a campus — not a park chosen because a
label fits there. `validate.py` only checks that every id
resolves to a real, distinct place; the judgement of *which* places belong is
yours. Omit the constant entirely for a city that isn't ready for this yet — the
engine checks `typeof LANDMARKS!=='undefined'` and simply skips the feature.

## Rules the validator enforces

- Records match `schemas/place.schema.json`; category and area keys resolve; coordinates inside `CITY.bounds`; at least `validate.minPlaces` places
- Place names unique; ids unique and present; `sameComplex` symmetric; `LANDMARKS` resolve
- `note` is `{zh,en}`, both non-empty, the English contains no Chinese; translations all-or-nothing and never a copy of the English
- Hours objects are renderable, closing no later than 24:00; no open-air record claims 24-hour opening
- Every record has a valid `src`; `official` is backed by a `w`; `v` not older than 6 months (warning) / 12 months (failure)
- Every `tag`/`pq`/`k`/`q` key is defined in all six languages; all six languages have identical key sets
- One language's punctuation never leaks into another's sentence templates; no address contains Chinese
- House wording: no 新移民 for the reader, no `$` figures or ratings in notes, no email inside `p`
- No literal city / agency / school district name in translated copy
- No `TODO:` left anywhere in the city (a draft city only warns on launch-readiness rules, never on this)
- City settings: `police` present; every `upcc` id is a `hospital` place; a city with routes has its own `busCoverage` stating the route count, `busFareText`, `BUS_SOURCE` and `examples.stop`; a city with open data or routes has a non-empty `licenceData`
- Clocks: `VERIFIED` not more than 45 days behind `DATA_VERSION`; `tasksChecked` not more than 60 days behind; `holidays` present and not about to run out
- Province: `holidays`, `hotlines`, `help.info` and the shared `seasons` equal `provinces/<province>/province.json`
- Task cards: every `place` id exists and is of a category the card allows; `QUARANTINE` records never reappear in `P`
- Map imagery: no OpenStreetMap volunteer tiles; the tile host is allowed by `worker.js`
- The engine contains no city data, no local phone number (outside a short list of province-wide services) and no place id of any city, and still has its `/*__CITY_DATA__*/` marker
- The page parses under an ES2017 syntax floor; no `hidden` attribute is defeated by a `display` rule

## `TASKS` — task cards

One object per card: `id`, `icon`, `when` (`first` / `ongoing` / `problem` — the three groups), `q` (the reader's question),
`t` (title), `why`, `steps`, `bring`, `cost`, `wait`, `deadline` / `due`, `place` (a place id), `src` and `srcName` (the
official page it was checked against; optional `srcL` / `srcNameL`, e.g. `{"fr": …}`, give the same page in another language where the agency publishes one — the URL can't be guessed by swapping `/en/` for `/fr/`), `help`, `also`, `say` and `sayGloss` (what to say at the counter), `confid`, `note`,
`alias` — each text in six languages. `checked` (optional, `YYYY-MM-DD`): the day this card alone was read against its sources again; the card footer shows it instead of `tasksChecked` (2026-10-20). **Never add or remove a step on a live card**: readers' ticks are stored by position.
Kelowna's cards are generated by `scripts/importers/tasks_from.py` from Kamloops' plus `import/task-overrides.json`.

## `QUARANTINE`

Places taken off the map: the full record plus a `quarantined` reason. Kept, never shown, and `validate.py` fails if one
reappears in `P`. Use it for a place that may have closed or cannot be verified, instead of deleting the evidence.

## `import/` (cities built with the importers; not read by the build)

| File | Holds |
|---|---|
| `config.json` | Importer settings: area anchors (`areaAnchors`), dataset localities, school-district list and official names (`bc_schools.names`), ArcGIS fields, and `categoriesNotCollected` (categories the reference city has that this one deliberately leaves out, with the reason) |
| `provenance.json` | `{id: {source, key, imported, …}}` — lets each importer find and replace its own records |
| `verification.json` | Desk checks by an independent second reader (see `src` above) |
| `translations.json` | `{id: {src_en, fr, es, ko, ja}}` — a translation goes stale when the English it was made from changes |
| `hours.json` | Official opening-hours wording per place; only fully understood wording becomes `h` |
| `task-overrides.json` | Local places and texts for the task cards (`scripts/importers/tasks_from.py`) |
| `research/*.json` | Raw official-site research batches; `_held_for_review` rows stay off the map |
| `school-phones-cache.json`, `<district>-sites.json` | School websites and phones |

## Rules it can't check — your judgement

- Whether a fact is **true**, and whether it is **still** true
- Whether a place is worth including at all — 250 chosen from thousands is the
  actual product
- Whether a note says something a reader can't get from Google
- Whether a category with one entry earns its place in the taxonomy

## Two categories that keep getting confused

`gov` and `commctr` have caught out two separate reviewers, so:

- **`gov`** — an office you go to in order to deal with a government or a
  government-funded programme: Service Canada, Service BC, ICBC, and settlement
  agencies delivering federally funded programmes.
- **`commctr`** — a place the community gathers, run by the city or by a cultural
  association: recreation centres, cultural centres, halls.

If it is somewhere you go to *complete a formality*, it is `gov`. If it is somewhere
you go to *spend time*, it is `commctr`.

`apt` and `propmgmt` divide the same way: `apt` is a building you could live in,
`propmgmt` is a company you phone. Do not put a management office in `apt` — it
inflates the count a person uses to judge how much choice they have.

## Adding a city

Follow `docs/guides/新城市操作手册.md`. In short: `python3 scripts/new-city.py <id> --name <Name> --centre <lat>,<lng>`
creates the skeleton — BC-wide parts copied, every city fact (transit page, school district, police line, campus, settlement
line, task-card check date, local lines) marked `TODO:`, the reference city's own texts removed so the engine defaults apply —
and `validate.py` refuses the city until every TODO is gone. Then import, research, desk-check, translate and verify; check
with `python3 scripts/validate.py --city <id>` and `tests/city_guitest.py --city <id>`. A city in another province needs a
province pack first (methodology §2).
