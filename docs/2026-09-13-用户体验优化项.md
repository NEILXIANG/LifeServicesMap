# 用户体验优化项（v2026.09.13a 之后・仅分析，暂不修改）

日期：2026-09-13 · 依据：三路审计的"顺手观察"、四轮从零扫描留下的未修项、以及这周对手机/平板/桌面的实机走查。每项写清：**问题**（用户实际会遇到什么）→ **方案** → **代价与收益**。按建议顺序排列。

## 一、第一次使用（前 30 秒）

1. **首屏仍然是"两个入口并列"，人要做一次选择。**
   问题：蓝色"遇到问题怎么办？"和搜索框都在首屏，第一次来的人不知道该先点哪个；首次卡片解释了三件事，但解释本身也是要读的东西。
   方案：搜索框接管首次引导——占位文字轮播三个真实问题（"怎么办医保卡？""哪路车到 TRU？""附近哪家药房现在开着？"），点进搜索框即出现 4 条建议（两条指南卡、两条地图查询），首次卡片缩成一行"免费・不用注册・不收集信息"。
   代价：中（搜索建议是新组件，六语文案）。收益：高——把"选择"变成"照着问"。

2. **从传单扫码进来的人，看到的和老用户一样多。**
   问题：`?src=flyer-*` 只影响快捷选择排序；传单上承诺的"三件事"没有在页面上接住。
   方案：带 `src=flyer-*` 进入时，首次卡片直接列出传单上的三个问题作为三个按钮（医保、工卡、去哪办），点一下进对应卡。
   代价：低（复用 firstUse 与 openTask）。收益：中高——扫码转化率是传单唯一能衡量的指标。

3. **深链接进卡后，要按三次返回才能离开。**
   问题：从传单/分享链接直接落到一张卡，Back 是 卡→列表→关闭→离开；对"只想看这一张"的人偏多。
   方案：深链接进入时只推一层历史（卡），Back 直接离开；仅在用户自己点"返回全部事项"后才建立列表那一层。
   代价：低。收益：中。

## 二、指南（办事卡）

4. **卡片是"读"的，不是"做"的。**
   问题：步骤是编号文字；办到第几步没有记录；下次打开又从头看。
   方案：步骤前加勾选框（存本地），"标记为已办好"改为自动——全部步骤勾完即完成；进度条按步骤而不是按卡计。
   代价：中（数据结构不变，只加本地状态；回归里"已办好"相关约 10 项要跟）。收益：高——这是让人"回来"的机制。

5. **"要带什么"没有清单形态。**
   问题：证件写成一段话，在柜台前对照不方便。
   方案：改为可勾选清单，打印版也印成方框。
   代价：低（数据层把 bring 拆成数组，六语）。收益：中。

6. **卡片里的"去哪里办"只有一个地点。**
   问题：SIN/MSP 这类有多个办理点（线上、邮寄、Service BC 多个门店），卡片只列一个。
   方案：place 支持数组，卡片列"最近的"+"其他办理点"，配合"附近"按距离排序。
   代价：中。收益：中（对北岸/Westsyde 居民尤其有用）。

7. **到达日期只服务三张卡。**
   问题：填了日期后只有驾照/报税/人权三条倒计时；其他卡没有"该什么时候做"。
   方案：每张卡加一个 `when` 的相对时间（"第 1 周""第 1 个月内""随时"），列表按时间线排；进度条显示"本周该做的"。
   代价：低（数据字段已有 `when:first/ongoing/problem`，细化即可）。收益：中高。

## 三、地图与筛选

8. **四个筛选按钮 + 快捷选择 + 搜索，三套入口做一件事。**
   问题：新用户看到三种"缩小范围"的方式，不知道差别；筛选行在法语/西语会折成三行。
   方案（Apple 方向，之前已论证）：一个"筛选"按钮打开一张 sheet，里面分页：区域 / 分类 / 主题 / 公交；快捷选择保留为"场景"；筛选条芯片不变。
   代价：高（回归里围绕四个按钮的选择器约 40 处）。收益：中高——首屏少一行，手机地图多 44px。

9. **地点气泡（popup）在手机上仍是锚定在图钉上的小窗。**
   问题：内容多时要在气泡内滚动；关闭要点小 ✕；换地点要先关再点。
   方案：Apple Maps 式底部地点卡：点图钉从底部升起半屏卡，可上滑展开全文，左右滑切换同分类的邻近地点；桌面保留气泡。
   代价：高（三十多项回归围绕气泡）。收益：高——这是手机上最常用的动作。

10. **公交只回答"这条线经过哪"，不回答"我怎么去"。**
    问题：用户的问题是"从我这到 RIH 坐几路"，现在要自己看 14 条线。
    方案 A（低）：地点卡片里显示"最近的站 + 经过线路"（站点数据已有，算最近站即可）。方案 B（中）：输入起点终点，给出"同一条线可直达"的判断（不做换乘）。
    代价：A 低 / B 中。收益：中高。

11. **"附近"只画一个点，不改变列表。**
    问题：定位后地图有蓝点，但地点没有按距离排序或显示距离。
    方案：定位成功后，气泡与收藏列表显示"1.2 km"，搜索结果按距离排；快捷选择加"步行 15 分钟内"。
    代价：低中。收益：中。

12. **18 条"大致位置"仍然靠文字提示。**
    问题：读者要读到提示才知道图钉可能偏。
    方案：这类图钉用空心/虚线样式，气泡顶部一条"位置为大致，导航按地址"。根治仍需实地落点。
    代价：低。收益：低中（诚实但不解决）。

## 四、语言与文字

13. **六语切换是分段控件，第七种语言放不下。**
    问题：320px 已经勉强；加旁遮普语后需要换形态。
    方案：语言按钮改为一个带当前语言名的下拉/sheet（Apple 设置里的做法），并按浏览器语言把可能的那一种排前面。
    代价：低中。收益：为扩语言铺路。

14. **正文字号偏小一档，层级只有两级。**
    问题：地点备注 12px、卡片正文 13px，年长读者（工具的目标人群之一）吃力。
    方案：正文 +1–2px，标题三级（页・区・条），并尊重系统"更大字体"设置（Dynamic Type 的 web 等价：用 rem 与 `font-size: -apple-system-body`）。
    代价：中（动全部布局基线，需重过手机 40% 地图底线）。收益：中高。

15. **emoji 当图标。**
    问题：不同手机 emoji 风格不一，在 Windows 上偏卡通，与 Apple 系统风格差距最大。
    方案：一套约 30 个单色 SVG（Apple SF Symbols 风格），分类色只给图钉，不给图标。
    代价：中高。收益：视觉一致，识别度更好。

## 五、信任与亲切感

16. **没有一张真实照片。**
    问题：地点是名字+地址，读者去之前不知道门脸长什么样；对"敢不敢进去"影响很大。
    方案：门脸照片（自拍或机构授权），先做 20 个最常去的办公室；照片进气泡与办事卡"去哪里办"。
    代价：需要有人实地拍摄。收益：高（亲切感的最直接来源）。

17. **"卡住了找谁"只有电话。**
    问题：不敢打电话的人（语言、社交焦虑）没有下一步。
    方案：加"可以发邮件/可以走进去"的选项，并标注"有中文/韩文工作人员"的机构（数据字段 `lang`）。
    代价：低中（需核实各机构语言能力）。收益：中高。

18. **纠错入口只有一个 mailto。**
    问题：发现错误的人要写邮件，门槛高，多数人放弃。
    方案：气泡里一个"这里有误"按钮，预填地点名与字段，仍走邮件（不收集数据、不需要后端），一键发出。
    代价：低。收益：中——纠错数量是数据质量的来源。

## 六、性能与可及

19. **单文件 1.39 MB。**
    问题：3G/弱网用户首个图钉要 5 秒以上。
    方案：按区懒加载地点数据；首屏只带指南 + 当前区域。
    代价：高（架构）。收益：弱网用户的第一印象。

20. **横屏平板与桌面的空白。**
    问题：1920px 桌面上地图两侧留白很大，指南弹窗仍是 600px 居中。
    方案：≥1400px 时指南改为右侧常驻栏（列表+卡），地图在左；筛选变左侧栏。
    代价：中高。收益：桌面/前台电脑场景（市政府柜台就是这种）。

## 建议顺序

先做 1、2、3、4、7、18（都低中代价，直接作用于"第一次用"和"回来用"），再做 10A、11、13，然后是 8、9、14、15 这四项"Apple 方向"的大改，16 与 19 视人力与数据情况另排。

## v2026.09.13c：底图更换 + 视觉与交互复审

**底图**：OpenStreetMap 志愿者瓦片服务器把本站拉黑（"Access blocked"）。其政策禁止向公众分发的应用直接使用；本地回归测试的无头浏览器（无 Referer、反复加载）在它看来就是抓取器。换成 CARTO Voyager（OSM 数据、CARTO 托管、允许公开网页带署名免费使用），Worker CSP 放行 `*.basemaps.cartocdn.com`，六语隐私说明的第三方名单同步，validate 新增"瓦片主机不得是 OSM 且必须在 CSP 里"的检查，回归脚本从此屏蔽所有瓦片请求。流量上去后的下一步：带密钥的商业底图（MapTiler / Stadia）或自托管 Kamloops 范围瓦片。

**视觉复审（19 条，全部修）**：手机语言按钮压住标题（`position:relative` 继承了桌面的 `top:24px`）；搜索建议在文档流里把整页往下推 → 改为绝对定位浮层且高于 Leaflet 控件；平板 601–1100px 标题/副标题跑到右侧控件下面、触屏平板 44px 控件互相重叠；320px 传单按钮溢出卡片 → 竖排可换行；线路号按颜色作字色（黄字 1.9:1）→ 墨色字 + 彩色描边；手机搜索框出现 ✕ 时高度从 48 跳到 62；焦点框把胶囊变方角、在快捷行里被裁；桌面离线提示与"附近"按钮重叠；320px 英/法/西头部折成两行 → 窄屏语言按钮只显示代码；传单按钮图标与文字无间距；残留 emoji（语言按钮、面板标题、分享/说明标题、线路标签/指示条/状态行、离线提示、重置按钮）；语言菜单项居中且按钮无展开态、列表用代码而非语言名；建议浮层比搜索框宽 2px；两条建议共用一个图标 → 新增药丸图标；步骤编号低于文字基线 → CSS 计数器；地点卡片"电话/官网"是 Leaflet 的青色 → 应用蓝；页眉链接悬停下划线跨到图标；两种列表芯片字号不一；分组标题图标颜色与文字不一致、指南图标被主题标题复用 → 新增图层图标；390px 英文四个筛选按钮折行。

**交互复审（9 条，全部修）**：**P0** 从链接进卡→返回全部→开另一张卡→✕ 会把浏览器退出网站（卡片层压在没有指南层的历史上，关闭时 `history.go(-2)` 越过了页面）→ 卡片层只在指南层之上才推入，关闭指南时清空 `_taskOpen`；**P1** 桌面上"哪路车到 TRU"建议打开公交面板又被"点在面板外"逻辑立即关闭；**P1** 键盘 Tab 进不了搜索建议（失焦即隐藏）→ 焦点在建议内不隐藏、Escape 回搜索框；仅"步行 15 分钟内"时不显示重置/撤销；从地点卡片选线路会因缩放重聚合而关掉卡片 → 从卡片选线不重新取景；经"门"打开的卡在此前关过一次后丢失自己的返回层；深链接刷新丢卡 → 打开的卡写入 `?task=`；横屏手机（844×390）套用手机头部布局并在跨过断点时重绘语言菜单；无障碍名称去掉表情符号。

回归：第 75 轮 14 项。
