## 四、状态是什么意思

| 状态 | 含义 | 由谁保证 |
|---|---|---|
| ✅ 自动检查 | 做错了会有检查失败或报出差距（validate、测试、一致性检查、审核清单、部署门禁） | `scripts/knowledge.py` 核对：至少有一个检查类条目，且标记字符串仍在那个文件里 |
| 🔧 工具保证 | 工具本身按规则做（导入规则、引擎行为），但没有会失败的检查 | 同上，核对工具文件和标记 |
| 📄 只有文档 | 只写在方法论、手册或提示词里，靠人记住 | 每轮迭代挑几条变成检查或工具 |
| ⏳ 待落实 | 已经决定要做，还没做 | 列在经验库"待办"里 |

`scripts/check-all.sh` 每次都跑 `python3 scripts/knowledge.py --check`：经验声称的检查被改名或删除、引用的文件或章节不存在、
文档里引用了不存在的编号、生成的页面过期——任何一项都会失败。所以经验库不会悄悄过时。

## 五、怎么加一条经验（每轮迭代结束时）

1. 迭代日志照常写：做了什么 → 发现 → 改了什么 → 三关复查。
2. 在 [`lessons.json`](lessons.json) 末尾加一条，编号接着往下（不复用、不重排）：
   - `title`：一句话结论；`lesson`：发生了什么；`rule`：变成的规则；
   - `area`：12 个领域之一；`scope`：all / CA / BC / city；`phase`：在流程哪一步用到；
   - `evidence`：证据文件和章节（例如迭代日志的"## 第 16 轮"）；
   - `encoded`：规则落在哪里（`kind` + 文件 + 文件里一定存在的标记字符串）；
   - `status`：auto / tool / doc / todo——**按实际情况填**，脚本会核对。
3. 同一条经验以后又被证实或加强：在原条目里加证据，不新开一条。
4. 运行 `python3 scripts/knowledge.py` 重新生成页面，再跑 `./scripts/check-all.sh --quick`。
5. "只有文档"变成了检查：把新的检查加进 `encoded`，状态改成 `auto`。

## 六、术语

| 术语 | 意思 |
|---|---|
| 参照城市 | 拿来对照的已上线城市（现在是 Kamloops） |
| 来源分级 `src` | opendata（政府开放数据）/ official（机构官网，附 `w`）/ places（第三方）/ own（电话或到场核实）/ stub-pending-verify（待核实） |
| 核实月份 `v` | 这条记录最后一次逐条核对的月份；不能批量写 |
| 独立复核 | 另一个读者对照官网逐字段复核，结果在 `import/verification.json`；不等于电话核实 |
| 安全相关类别 | 医疗、药房、牙科、庇护所与危机、食物银行、安置与政府、法律、警察 |
| 同口径 | 和参照城市按同一规则计算指标（例如营业时间都不计露天、托儿、学校） |
| 草稿 | `city.json` 里 `"status": "draft"`：上线类规则只警告，不能部署 |
| 可选模块 | 有就显示、没有就整块不出现的功能（公交、校园、本地危机小组） |
| 省包 / 国家包 | 第一个外省或美国城市之前，要从引擎里搬出来的省、国家级内容（尚未建立） |
