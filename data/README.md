# `data/` 目录说明

本目录存放**运营 / 分析 / 反馈记录**，与 `src/data-kamloops.js` 中的「应用数据」是两件事。

## 文件清单

| 文件 | 用途 | 维护频率 |
|---|---|---|
| `analytics-log.md` | Cloudflare Metrics / Web Analytics 周报 | 每周 |
| `data-quality-log.md` | 数据本身待修复 / 待补充 / 待核实 | 每两周 |
| `feedback-log.md` | 用户反馈（群聊 / 邮件 / 私信） | 实时记 |
| `business-hypothesis.md` | 商业化假设与验证状态 | 每月底更新 |

完整框架见 `docs/archive/2026-09-04-数据记录与商业化探索框架.md`。

---

## 字段命名约定

- 日期统一 `YYYY-MM-DD`（如 `2026-09-04`）
- 周次用 `YYYY-Www`（如 `2026-W36`）
- 链接统一 `[文字](URL)` 格式
- 截图统一存为相对路径 `./screenshots/...`（或 git-LFS / 单独网盘）
- 用户反馈隐去姓名 / 头像，只保留**地域 + 渠道 + 内容**

---

## 隐私原则

- **不上传个体行为数据**到任何服务器
- **不记录用户姓名、IP、设备 ID**
- 反馈去标识化（仅保留地域、渠道、内容摘要）
- 定期清理群聊截图（保留摘要即可）

---

## 上手顺序（本周内）

1. **接 Cloudflare Web Analytics**（一行 JS，详见上面那份框架文档第五节）→ 拿到浏览数据
2. **填 `analytics-log.md` 第 36 周那一节**：去 Dashboard 截图 + 填基线数据
3. **走一遍自查清单**（在 `data-quality-log.md` 底部）→ 把发现的问题填进去
4. **回看 `business-hypothesis.md` 的 5 条假设**：删掉你觉得不该做的（剩下的是真正想探索的）

## 何时不用记

- 短暂的 chat 提及（如"这工具不错"）——除非能转化为可操作信号
- 单次部署但无新功能 → `analytics-log.md` 加一行即可，不展开
- 三个月内无变化的假设 → 标记"待复核"，下个季度再决定
